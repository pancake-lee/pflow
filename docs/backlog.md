## #76 今日日程的执行队列与观测

- **状态**：WIP
- **背景**：现有「今日日程」可展示当前/下一项并记录完成或跳过，但执行中缺少开始、拖延、提前、调序等过程观测，也无法从事件进行日对账。原始需求见 [设计文档](design/2026-10-24-76-execution-queue.md)。
- **方案**：沿用现有日程及其计划顺序，在执行过程中加入动作记录、积分、对账和轻量出口。日程编辑、模板和当天计划的配置保持现状；每个子任务可单独裁剪，组合时仅需保留其列明的依赖。被裁剪的子任务不计入父任务验收。
- **分析**：#76.2 基于现有日程提供动作事件；#76.3–#76.5 可按需组合，#76.6 是手机入口。现有时间轴、跨午夜、模板快照及手动推进语义应保留。
- **验收**：保留的子任务各自通过验收，现有日程及项目注意力引导无回归；完整组合时可完成设计文档首页全部验证场景。

### #76.2 动作日志与积分

- **状态**：待用户验收
- **分组**：#76 今日日程的执行队列与观测
- **依赖**：现有「今日日程」，无需其他 #76 子任务。
- **背景**：只有完成与跳过状态，无法追溯开始、提前、调序或拖延，也无法核对偏离成本。
- **方案**：基于已保存的日程顺序，在原执行入口加入开始、完成、跳过、提前、运行时调序和拖延，保存不可改写的动作事件与可追加备注；按固定规则从事件计算完成 +10、跳过/调序 −3，其余动作 0。运行时调序不改写日程项或模板。
- **验收**：每个动作留下正确事件与分数；提前完成不重复执行或扣分，重复请求不重复记分；执行偏离不改动已保存的日程配置；刷新及重启后记录保留，写入失败不显示成功。
- **AI 自动验证**：`make test`、`make build`、`make vet` 通过；日程单测覆盖提前、调序、重复动作和非法跨项完成，API 测试覆盖重复提交与持久化。
- **（用户）验收操作**：在 Dashboard 的已有四项日程中依次试开始、提前完成下一项、调序更后面的项，并刷新页面。
- **预期结果**：动作日志和积分与设计一致，已保存的日程项及模板未改变。
- **最小回传**：与其余 #76 子任务合并试跑后，回复「#76 已通过」。

### #76.3 日对账

- **状态**：已规划
- **分组**：#76 今日日程的执行队列与观测
- **依赖**：#76.2。
- **背景**：仅靠当天记忆难以核对完成、偏离和耗时。
- **方案**：从动作事件汇总总分、完成项、偏离次数和可计算耗时，展示日志并允许记录一个可留空的明日调整点；历史旧记录缺少事件时明确标示缺口。
- **验收**：一天试跑后可从日志核对汇总，旧记录不伪造耗时或积分；对账可在五分钟内完成。

### #76.4 停车场与维护窗口

- **状态**：已规划
- **分组**：#76 今日日程的执行队列与观测
- **依赖**：#76.2。
- **背景**：执行中冒出的可延期小事会反复占用注意力。
- **方案**：在当前项旁提供一句话收纳，作为事件保存；用户在现有日程安排的维护时段主动打开停车场，不新增类别或计划字段。
- **验收**：收纳不改变当前项，内容重启后仍在；主动打开时可查看并标记处理。

### #76.5 应用内暂离

- **状态**：已规划
- **分组**：#76 今日日程的执行队列与观测
- **依赖**：#76.2。
- **背景**：主动切走时缺少返回线索，但浏览器无法可靠检测所有外部切换。
- **方案**：提供用户主动触发的暂离入口；输入一句切换意图或等待 10 秒即可继续，记录事件并在返回时展示原当前项与线索。
- **验收**：两种暂离路径均可离开并恢复线索；无需系统权限，不把最小化或关闭浏览器当作必定可检测事件。

### #76.6 手机快捷记录

- **状态**：已规划
- **分组**：#76 今日日程的执行队列与观测
- **依赖**：#76.5。
- **背景**：离开电脑时需要低操作成本地记下当前意图或返回线索。
- **方案**：在连接同一 pflow 服务的手机浏览器提供适配窄屏的快捷记录入口，复用暂离事件和返回线索。
- **验收**：手机浏览器能快速记录并在电脑端看到同一线索；不要求离线同步或系统权限。

## 产品定位决策

**从**：多 Agent 会话的状态查看工具
**到**：多 Agent 会话的注意力管理与调度工具，让用户能快速判断下一步该关注哪一路 Agent。

核心 workflow：启动 Agent → 自动发现会话 → 按项目归类 → Dashboard 汇总状态 → 用户依据提醒和建议进行关注、授权或切换。

**主动不做的事**：

- 不替代 Claude Code、Hermes 或其他 Agent 的对话和执行能力。
- 不自动替用户批准高风险操作。
- 不在 Dashboard 中复制完整的 Agent 工作界面。

## 拒绝清单

- 以独立项目 ID/名称实体替代“路径即项目”模型。
- 通过抓取终端渲染内容承载所有 Agent 状态，优先使用稳定的 JSON 或明确命令输出。
- 在 pflow 内自建 WebSocket + PTY 桥接，优先复用成熟的 ttyd + tmux 链路。
