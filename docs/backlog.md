## 任务详情

### #85 当前日程记录偏差与实际工作内容

- **状态**：待规划
- **关联中枢**：[今日日程执行与观测](design/2026-10-25-76-execution-queue-hub.md)
- **背景**：用户在实际工作中可能用其他有价值的工作替代当前日程。未按计划执行需要如实记录，但不能把实际工作的价值等同于零。目前当前项的主要出口是完成和跳过，补卡属于完成，暂离后还会回来，不属于出口。需要增加「记录偏差」，作为当前项的另一类结束方式。
- **需求**：
  - 当前日程操作区增加「记录偏差」按钮。
  - 点击后打开弹窗，提供文本输入框，记录实际做了什么事。
  - 弹窗提供自定义分数输入框，默认值为 +5 分，认可实际工作价值，同时体现未按原计划执行与按计划完成 +10 分的区别。
  - 提交后结束当前项并推进下一项；取消弹窗不结束日程、不计分。
  - 日对账配套展示「记录偏差」记录，关联原日程、实际工作内容、操作时间和实际得分；当天积分及标准分使用本次实际得分。
- **方案**：待规划，本轮仅登记需求。
- **分析**：现有实现已覆盖当前项推进、执行计时、逐事件积分与日对账展示，规划时需一起梳理。需明确自定义分数的允许范围与精度，以及该出口在完成数和偏离数中的统计口径；不能直接套用普通完成或跳过的固定分值。
- **待办**：
  - [ ] 明确分数输入规则及完成数、偏离数统计口径。
  - [ ] 规划弹窗、当前项结束与计时、事件保存和日对账展示的一致行为，将实施步骤补入本条目。
  - [ ] 实现并验证默认 +5、自定义分数、取消、重复提交及历史记录兼容，交付前完成自动验证。
- **验收**：
  - [ ] 当前项可通过「记录偏差」打开弹窗，输入实际工作内容，分数默认 +5 且可修改。
  - [ ] 成功提交后当前项结束、计时收束并推进下一项，同一项不能重复计分。
  - [ ] 取消弹窗不改变当前项与积分；保存失败时保留输入并提示。
  - [ ] 日对账能查到原日程、实际工作内容、记录时间与实际得分，积分和统计遵循最终确认的口径。
  - [ ] 既有完成、补卡、跳过、暂离及历史日对账记录继续正常使用。

## 产品定位决策

**从**：多 Agent 会话的状态查看工具
**到**：多 Agent 会话的注意力管理与调度工具，让用户能快速判断下一步该关注哪一路 Agent。

核心 workflow：启动 Agent → 自动发现会话 → 按项目归类 → Dashboard 汇总状态 → 用户依据提醒和建议进行关注、授权或切换。

**主动不做的事**：

- 不替代 Claude Code、Hermes 或其他 Agent 的对话和执行能力。
- 不自动替用户批准高风险操作。
- 不在 Dashboard 中复制完整的 Agent 工作界面。

## 拒绝清单

- 以独立项目 ID/名称实体替代“路径即项目”模型。
- 通过抓取终端渲染内容承载所有 Agent 状态，优先使用稳定的 JSON 或明确命令输出。
- 在 pflow 内自建 WebSocket + PTY 桥接，优先复用成熟的 ttyd + tmux 链路。
