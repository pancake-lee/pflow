## 注意力通知

### #19 桌面通知

- **状态**：待规划
- **分组**：注意力通知
- **背景**：当前提醒分数只在 Dashboard 中展示，用户离开页面后无法及时获知需要关注的项目。
- **分析**：浏览器 Notification API 可以补足页面外提醒，但需要处理权限、阈值、重复通知和用户拒绝等状态。
- **方案**：待规划。方案应定义通知触发、去重、权限管理和用户可控边界，并与现有提醒分数保持一致。
- **验收**：通知权限、阈值触发、重复通知抑制和权限拒绝均有明确行为。

### #20 军情哨主动推送

- **状态**：待规划
- **分组**：注意力通知
- **背景**：当前军情哨主要随 Dashboard 请求生成，后台没有持续主动推送能力。
- **分析**：主动推送依赖后台守护进程和可靠推送通道，需要明确服务生命周期、推送时机和失败重试边界。
- **方案**：待规划。方案应定义后台计算、推送通道、消息去重和用户关闭策略。
- **依赖**：需要后台守护进程和可靠的推送通道。
- **验收**：服务在无页面主动刷新时仍能按规则推送，并能查看推送原因和时间。

### #21 统帅偏好学习

- **状态**：待规划
- **分组**：注意力通知
- **背景**：当前提醒频率由固定规则决定，没有利用用户响应和忽略行为调整提醒策略。
- **分析**：偏好学习需要区分用户主动忽略、已处理和暂时离开等行为，避免学习结果突破用户设定的通知边界。
- **方案**：待规划。方案应定义反馈信号、偏好模型、可解释性、重置方式和安全边界。
- **验收**：偏好数据可解释、可重置，学习结果不会突破用户设定的通知边界。

## 视觉扩展

### #23 双层换肤系统

- **状态**：待规划
- **分组**：视觉扩展
- **背景**：当前界面已通过 CSS 变量为注意力遮罩预留扩展空间，但内容层和遮罩层还没有独立的主题管理能力。
- **分析**：内容层与注意力遮罩层的视觉职责不同，需要在保持提醒可读性和状态表达的前提下独立换肤。
- **方案**：待规划。现有设计文档作为后续规划输入，不提前固化实现细节。
- **设计依据**：[`design/99-dual_layer_skinning_system.md`](design/99-dual_layer_skinning_system.md)
- **验收**：皮肤可独立配置内容层和遮罩层，切换后不破坏提醒状态和可读性。

### #24 Web AI 平台状态监控

- **状态**：待规划
- **分组**：平台扩展
- **背景**：当前 pflow 监控 Claude Code 和 Hermes，会话范围尚未覆盖浏览器中的其他 AI 平台。
- **分析**：浏览器扩展需要在最小权限下读取平台状态，并将不同平台的会话状态转换为统一展示模型。
- **方案**：待规划。方案应定义扩展权限、平台适配边界、状态采集和 Dashboard 同步方式。
- **设计依据**：[`design/99-ai-chat-web-attach.md`](design/99-ai-chat-web-attach.md)
- **验收**：扩展按最小权限读取状态，Dashboard 能区分平台、会话和状态变化。

## 平台扩展

### #25 跨设备同步

- **状态**：待规划
- **分组**：平台扩展
- **背景**：当前 Dashboard 面向本机浏览器，没有手机或平板查看会话状态及执行批准操作的能力。
- **分析**：跨设备能力涉及身份认证、状态同步、远程授权和断线恢复，安全边界高于普通只读展示。
- **方案**：待规划。方案应先明确设备身份、同步范围、授权确认和离线行为。
- **验收**：跨设备身份、状态同步、授权安全和离线/断线行为有明确方案。

## Agent 扩展

### #26 更多 Agent 类型支持

- **状态**：待规划
- **分组**：Agent 扩展
- **背景**：当前已支持 Claude Code 和 Hermes，其他 Agent 尚未接入统一会话模型。
- **分析**：不同 Agent 的启动方式、会话标识和状态采集方式存在差异，需要先抽象适配边界和统一展示契约。
- **方案**：待规划。方案应定义 Agent 适配接口、会话生命周期、状态采集和 Dashboard 展示方式。
- **验收**：Agent 适配边界、会话标识、状态采集和 Dashboard 展示方式统一。

## 产品定位决策

**从**：多 Agent 会话的状态查看工具
**到**：多 Agent 会话的注意力管理与调度工具，让用户能快速判断下一步该关注哪一路 Agent。

核心 workflow：启动 Agent → 自动发现会话 → 按项目归类 → Dashboard 汇总状态 → 用户依据提醒和建议进行关注、授权或切换。

**主动不做的事**：

- 不替代 Claude Code、Hermes 或其他 Agent 的对话和执行能力。
- 不自动替用户批准高风险操作。
- 不在 Dashboard 中复制完整的 Agent 工作界面。

## 拒绝清单
