## #76 今日日程的执行队列与观测

- **状态**：待用户验收
- **背景**：现有「今日日程」可展示当前/下一项并记录完成或跳过，但执行中缺少开始、拖延、提前、调序等过程观测，也无法从事件进行日对账。原始需求见 [设计文档](design/2026-10-24-76-execution-queue.md)。
- **方案**：沿用现有日程及其计划顺序，在执行过程中加入动作记录、积分、对账和轻量出口。日程编辑、模板和当天计划的配置保持现状；每个子任务可单独裁剪，组合时仅需保留其列明的依赖。被裁剪的子任务不计入父任务验收。
- **分析**：#76.2 基于现有日程提供动作事件；#76.3–#76.5 可按需组合，#76.6 是手机入口。现有时间轴、跨午夜、模板快照及手动推进语义应保留。
- **验收**：保留的子任务各自通过验收，现有日程及项目注意力引导无回归；完整组合时可完成设计文档首页全部验证场景。
- **AI 自动验证**：各子任务已分别通过针对性测试与构建；整组最终执行 `make test`、`make vet`、`make build`，并核对事件、积分、旧记录缺口、停车场、暂离和窄屏入口。
- **实施记录**：2026-10-25 根据界面反馈，移除「开始」按钮并在当前项首次显示时自动记录开始；日程外围容器统一承载编辑、停车场、调序下拉列表和日对账弹窗。独立操作日志入口已合并进弹窗。`make test`、`pnpm run test:schedule`（43 项）和 `make build` 通过。
- **（用户）验收操作**：用已有四项日程完成一次试跑，观察当前项自动计时、顶部全局操作和日对账弹窗，再体验停车场、两种暂离方式，并用手机浏览器连接同一服务记录线索。
- **预期结果**：页面行为与[设计文档首页验证任务](design/2026-10-24-76-execution-queue.md#可执行任务与验证)一致；日程及模板配置不变，手机线索可在电脑端看到。
- **最小回传**：回复「#76 已通过」；无需导出系统已有日志。
- **关单方式**：收到确认后，在同一轮将父任务与 #76.2–#76.6 标为 `Done`，同步总览和详情，不反向核验用户结论。

### #76.2 动作日志与积分

- **状态**：待用户验收
- **分组**：#76 今日日程的执行队列与观测
- **依赖**：现有「今日日程」，无需其他 #76 子任务。
- **背景**：只有完成与跳过状态，无法追溯开始、提前、调序或拖延，也无法核对偏离成本。
- **方案**：基于已保存的日程顺序，当前项首次在可见页面展示时自动记录开始；在当前项保留完成、跳过、拖延、暂离等局部操作，全局调序改为顶部下拉列表。保存不可改写的动作事件与可追加备注，按固定规则计算完成 +10、跳过/调序 −3，其余动作 0。运行时调序不改写日程项或模板。
- **验收**：每个动作留下正确事件与分数；当前项自动开始且刷新不重复记开始事件；提前完成不重复执行或扣分，重复请求不重复记分；执行偏离不改动已保存的日程配置；刷新及重启后记录保留，写入失败不显示成功。
- **AI 自动验证**：`make test`、`make build`、`make vet` 通过；日程单测覆盖提前、调序、重复动作和非法跨项完成，API 测试覆盖重复提交与持久化。
- **（用户）验收操作**：在 Dashboard 的已有四项日程中观察当前项自动计时，提前完成下一项，再从顶部下拉列表调序更后面的项，并刷新页面。
- **预期结果**：动作日志和积分与设计一致，已保存的日程项及模板未改变。
- **最小回传**：与其余 #76 子任务合并试跑后，回复「#76 已通过」。

### #76.3 日对账

- **状态**：待用户验收
- **分组**：#76 今日日程的执行队列与观测
- **依赖**：#76.2。
- **背景**：仅靠当天记忆难以核对完成、偏离和耗时。
- **方案**：从动作事件汇总总分、完成项、偏离次数和累计计时时长；顶部「日对账」打开弹窗，统一展示事件日志、当前项备注及可留空的明日调整点。历史旧记录缺少事件时明确标示缺口。
- **验收**：一天试跑后可从日志核对汇总，旧记录不伪造耗时或积分；对账可在五分钟内完成。
- **AI 自动验证**：`go test ./internal/schedule ./internal/api` 与 `make build` 通过；单测核对积分、完成数、偏离数、耗时及旧记录缺口，API 测试核对明日调整点持久化。
- **（用户）验收操作**：完成一天的动作后，从日程区域顶部打开「日对账」弹窗，核对汇总并保存一条明日调整点。
- **预期结果**：汇总与日志一致，调整点刷新后仍在，对账操作不超过五分钟。
- **最小回传**：与其余 #76 子任务合并试跑后，回复「#76 已通过」。

### #76.4 停车场与维护窗口

- **状态**：待用户验收
- **分组**：#76 今日日程的执行队列与观测
- **依赖**：#76.2。
- **背景**：执行中冒出的可延期小事会反复占用注意力。

- **验收**：收纳不改变当前项，内容重启后仍在；主动打开时可查看并标记处理。
- **AI 自动验证**：`go test ./internal/schedule ./internal/api` 与 `make build` 通过；测试覆盖空内容、重复处理、当前项不变及持久化。
- **（用户）验收操作**：执行日程时收纳一件琐事，稍后打开停车场并标记处理。
- **预期结果**：当前项不变，刷新后收纳内容和处理状态仍在。
- **最小回传**：与其余 #76 子任务合并试跑后，回复「#76 已通过」。

### #76.5 应用内暂离

- **状态**：待用户验收
- **分组**：#76 今日日程的执行队列与观测
- **依赖**：#76.2。
- **背景**：主动切走时缺少返回线索，但浏览器无法可靠检测所有外部切换。
- **方案**：提供用户主动触发的暂离入口；输入一句切换意图或等待 10 秒即可继续，记录事件并在返回时展示原当前项与线索。
- **验收**：两种暂离路径均可离开并恢复线索；无需系统权限，不把最小化或关闭浏览器当作必定可检测事件。
- **AI 自动验证**：`go test ./internal/schedule ./internal/api` 与 `make build` 通过；单测覆盖暂离、返回、重复返回及暂离期间禁止推进。
- **（用户）验收操作**：分别以「输入一句意图」和「留空等待 10 秒」方式暂离，刷新后点击返回。
- **预期结果**：两条路径均保留原当前项和返回线索，返回后可继续执行。
- **最小回传**：与其余 #76 子任务合并试跑后，回复「#76 已通过」。

### #76.6 手机快捷记录

- **状态**：待用户验收
- **分组**：#76 今日日程的执行队列与观测
- **依赖**：#76.5。
- **背景**：离开电脑时需要低操作成本地记下当前意图或返回线索。
- **方案**：在连接同一 pflow 服务的手机浏览器提供适配窄屏的快捷记录入口，复用暂离事件和返回线索。
- **验收**：手机浏览器能快速记录并在电脑端看到同一线索；不要求离线同步或系统权限。
- **AI 自动验证**：`pnpm run build`、`make test`、`make vet`、`make build` 通过；窄屏入口复用已测试的暂离事件 API，无新增服务端行为。
- **（用户）验收操作**：手机浏览器访问同一 pflow 服务，输入返回线索并点击「记录并暂离」，然后在电脑端打开 Dashboard。
- **预期结果**：电脑端显示同一条线索，点击返回后继续原当前项。
- **最小回传**：与其余 #76 子任务合并试跑后，回复「#76 已通过」。

## 产品定位决策

**从**：多 Agent 会话的状态查看工具
**到**：多 Agent 会话的注意力管理与调度工具，让用户能快速判断下一步该关注哪一路 Agent。

核心 workflow：启动 Agent → 自动发现会话 → 按项目归类 → Dashboard 汇总状态 → 用户依据提醒和建议进行关注、授权或切换。

**主动不做的事**：

- 不替代 Claude Code、Hermes 或其他 Agent 的对话和执行能力。
- 不自动替用户批准高风险操作。
- 不在 Dashboard 中复制完整的 Agent 工作界面。

## 拒绝清单

- 以独立项目 ID/名称实体替代“路径即项目”模型。
- 通过抓取终端渲染内容承载所有 Agent 状态，优先使用稳定的 JSON 或明确命令输出。
- 在 pflow 内自建 WebSocket + PTY 桥接，优先复用成熟的 ttyd + tmux 链路。
