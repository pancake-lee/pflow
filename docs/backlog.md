## 时间追踪

### #42 基于 tmux 焦点事件的项目计时

- **状态**：Done
- **分组**：时间追踪
- **背景**：现有活跃时间把 tmux attach、会话切换和 detach 当作焦点事件。用户切到编辑器、浏览器或其他应用时不会产生失焦记录，项目时间会被持续累计，不能代表实际窗口焦点。
- **分析**：当前环境已安装 tmux 3.7c，具备 `client-focus-in` 与 `client-focus-out` hooks。tmux 3.2a 不支持这些 hooks，无法提供本任务所需的准确事件。`focus-events` 必须持续启用，且用户终端需支持焦点报告；不具备事件能力时，项目时间应继续走既有消息估算链路。
- **方案**：`pflow serve` 保守合并 tmux 配置并同步运行时开关，只补充缺失的焦点事件设置，不覆盖用户其他配置或重复添加相同设置。服务注册新版 client focus hooks，将事件记录关联到 pflow 托管会话。项目时间聚合按跨项目切换立即截断，同项目在 5 分钟宽限期内恢复焦点时合并为同一连续时段；宽限期作为代码常量。无有效焦点数据时维持消息估算降级。
- **任务列表**：
  - [x] 42.1 实现 tmux 配置的保守检查、补充与运行时启用，并为已启用、缺失、显式关闭和包含其他用户配置的情况补充测试。
  - [x] 42.2 将焦点记录替换为 client focus 事件，识别不支持的 tmux 版本并保留可诊断的消息估算降级。
  - [x] 42.3 实现含 5 分钟同项目恢复宽限期的项目时间聚合，覆盖跨项目切换、同项目恢复、超时恢复、未闭合事件和异常事件序列。
  - [x] 42.4 接入 Dashboard、`pflow suggest` 和提醒评分，更新时间追踪说明并完成自动验证。
- **验收**：
  - [x] `pflow serve` 不改写已有 tmux 配置，只在缺失时补充一次 `focus-events on`，运行中 tmux 同步开启。
  - [x] 项目 A 切换至项目 B 时，A 在失焦时刻停止累计，B 从获焦时刻开始累计。
  - [x] 项目 A 失焦后 5 分钟内未切至其他项目且重新获得焦点，间隔合并进 A；超过 5 分钟不合并。
- [x] 无新版 hook、无焦点日志或日志无匹配项目时，Dashboard、行动建议和 CLI 均回退消息估算且不影响其他会话。

## 日程管理

### #46 日程模板与今日日程引导

- **状态**：Done
- **分组**：日程管理
- **背景**：用户目前使用外部 Markdown 文件规划一天，pflow 的 Dashboard 无法呈现个人时间节奏，也无法把“此刻该做什么”与项目注意力引导放在同一界面。用户希望复用日程编辑器管理多份模板，并将其提供的时间表直接作为首次可见数据。
- **分析**：日程既需随当前时间定位，又必须遵循 pflow “系统引导、不替用户行动”的原则，不能在时间到达时自动把用户切到下一项。break 应归属于其前一日程项，避免把休息误表示为待办。项目现有提醒与迷雾已经是正交的双维度模型，日程应复用视觉语言但不能与项目分数混算。详细交互、边界和验收见 [`design/2026-09-11-46-daily-schedule.md`](design/2026-09-11-46-daily-schedule.md)。
- **方案**：增加独立日程领域，以版本化、原子写入的本地 JSON 保存按日实际日程、模板和执行记录。提供单一编辑界面，按日期保存实际日程，并在其中完成模板应用、另存和删除；模板不直接编辑且不带执行记录。Dashboard 在标题栏下、筛选栏上方新增日程区域，展示当前项和下一项，空档用自由日程补足。首次按时间定位，其后仅由完成或跳过操作推进并记录结果。时间临近度单独产生日程提醒分和反向的迷雾分，下一项用渐进式清晰度表达；当前项保持清晰，进入其 break 时复用高亮跑马灯。首次初始化仅在不存在同日期数据时写入用户提供的当天时间表。
- **任务列表**：

  - [ ] 46.2 实现实际日程和模板的查询、保存、删除模板、应用模板及完成/跳过 API 边界；保证模板与实际执行记录隔离，替换已记录日程时要求明确确认。
  - [ ] 46.3 实现日期选择与复用的日程编辑界面，支持日程项、默认 10 分钟 break、持续至当天结束末项，以及模板的应用、另存和删除反馈。
  - [ ] 46.4 将当天日程状态聚合到 Dashboard，在标题栏下、筛选栏上方增加当前/下一日程区；实现自由日程、首次按时间定位和仅用户操作推进的状态机。
  - [ ] 46.5 实现日程提醒分、迷雾分和 break 高亮效果，复用现有跑马灯及半透明视觉映射但不影响项目注意力计算；覆盖临近、逾时、空档、break 和手动推进的时间边界测试。
  - [ ] 46.6 在开发环境安全写入用户提供的当天日程到本机用户数据，确保其不进入源码、测试夹具或提交文件，且不覆盖已有数据；完成 Go 格式化、`GOTOOLCHAIN=local make vet`、`GOTOOLCHAIN=local make test`、前端类型检查与构建验证。

- **状态**：Done

### #40 `make start` 误杀 Codex 会话

- **状态**：Done
- **分组**：服务管理
- **背景**：`make start` 会终止正在运行的 `pflow codex` 会话；预期只停止由该服务管理流程启动的 `pflow serve`。
- **分析**：主因位于 `pflow serve` 启动路径：`CleanOrphanSessions` 会销毁所有未出现在 `~/.pflow/mappings.json` 的 `pflow-*` tmux 会话。Codex 的映射依赖启动后的异步会话 ID 捕获，但实际 rollout JSONL 的第一行会在 tmux 启动约 52–57 秒后才首次落盘；现有捕获仅等待 15 秒，必然留下无映射的正常 Codex 会话，进而被 `tmux kill-session` 终止。日志已记录多次 `orphan: destroyed pflow-pflow-codex`，并且按真实启动时间复核，rollout 在捕获超时后可被扫描器找到。此外，`Makefile` 的 PID 文件仅保存数字 PID，也存在服务退出后 PID 复用而误杀其他进程的独立风险。
- **方案**：保留有价值的 tmux 孤儿清理，但改为基于完整生命周期信息判断：`pflow codex` 创建 tmux 会话时同步持久化一个待关联映射，以先声明该会话受 pflow 管理；后台持续重试关联 rollout，直到取得 Codex 会话 ID 后原子更新同一映射。`serve` 的清理逻辑只处理具备明确失效证据的已登记会话，映射缺失不能单独作为销毁依据，因而兼容旧版或异常启动留下的活跃会话。与此同时，将服务 PID 记录扩展为可验证的进程身份（PID 与 Linux 进程启动标识）；`stop` 与 `status` 身份不一致时仅清理陈旧记录，不操作该进程，并兼容旧 PID 文件的 `pflow serve` 命令核验。
- **任务列表**：
  - [x] 40.1 在 Codex tmux 创建时同步写入待关联映射；将 rollout 关联改为可持续重试，并在获得会话 ID 后更新映射。
  - [x] 40.2 保持 `serve` 的 tmux 孤儿清理规则不变，并让待关联映射参与既有清理判定。
  - [ ] 40.3 调整 `Makefile` 的服务身份记录、停止和状态检查逻辑，拒绝对身份不匹配的 PID 发信号。
  - [ ] 40.4 增加可重复验证：rollout 延迟超过 15 秒时 Codex 映射最终仍可建立且 `make start` 不会终止会话；陈旧 PID 与非 `serve` 进程均不会被终止；正常 `serve` 仍可启动、查询和停止。
- **验收**：
  - [x] rollout 延迟落盘时，`pflow codex` 会先存在待关联映射，随后自动关联到正确的 Codex 会话 ID。
  - [x] `pflow codex` 的映射缺失或捕获超时后，`make start` 不会终止其 tmux 会话、Codex 进程或外层客户端。

### #41 Claude 会话误报 waiting（同 sessionId 元数据覆盖）

## 产品定位决策

**从**：多 Agent 会话的状态查看工具
**到**：多 Agent 会话的注意力管理与调度工具，让用户能快速判断下一步该关注哪一路 Agent。

核心 workflow：启动 Agent → 自动发现会话 → 按项目归类 → Dashboard 汇总状态 → 用户依据提醒和建议进行关注、授权或切换。

**主动不做的事**：

- 不替代 Claude Code、Hermes 或其他 Agent 的对话和执行能力。
- 不自动替用户批准高风险操作。
- 不在 Dashboard 中复制完整的 Agent 工作界面。

## 拒绝清单

- 以独立项目 ID/名称实体替代“路径即项目”模型。
- 通过抓取终端渲染内容承载所有 Agent 状态，优先使用稳定的 JSON 或明确命令输出。
- 在 pflow 内自建 WebSocket + PTY 桥接，优先复用成熟的 ttyd + tmux 链路。
