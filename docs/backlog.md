## #76 今日日程的执行队列与观测

- **状态**：Done
- **评估**：7.7（正确性 7.2，健壮性 7.1，准确性 7.2，完整性 8.2，可维护性 7.3，简洁性 7.4，一致性 8.0，惊喜度 7.5，可用性 8.4，交互体验 8.1），详见 [评估报告](eval/reports/2026-10-25-76-execution-queue-review.md)。
- **背景**：现有「今日日程」可展示当前/下一项并记录完成或跳过，但执行中缺少开始、提前、跳转等过程观测，也无法从事件进行日对账。原始需求见 [设计文档](design/2026-10-24-76-execution-queue.md)。
- **方案**：沿用现有日程及其计划顺序，在执行过程中加入动作记录、积分、对账和轻量出口。日程编辑、模板和当天计划的配置保持现状；每个子任务可单独裁剪，组合时仅需保留其列明的依赖。被裁剪的子任务不计入父任务验收。
- **分析**：#76.2 基于现有日程提供动作事件；#76.3–#76.5 可按需组合，#76.6 是手机入口。现有时间轴、跨午夜、模板快照及手动推进语义应保留。
- **验收**：保留的子任务各自通过验收，现有日程及项目注意力引导无回归；完整组合时可完成设计文档首页全部验证场景。
- **AI 自动验证**：各子任务已分别通过针对性测试与构建；整组最终执行 `make test`、`make vet`、`make build`，并核对事件、积分、旧记录缺口、停车场、暂离和窄屏入口。
- **实施记录**：2026-10-25 根据界面反馈，移除「开始」和「拖延」按钮并在当前项首次显示时自动记录开始；日程外围容器统一承载跳转日程、编辑、停车场和日对账弹窗。独立操作日志入口已合并进弹窗；日对账改为按日期读取与独立备注。`make test`、`make vet`、`pnpm run test:schedule`（43 项）和 `make build` 通过。
- **（用户）验收操作**：用已有四项日程完成一次试跑，观察当前项自动计时、顶部全局操作和日对账弹窗，再体验停车场、两种暂离方式，并用手机浏览器连接同一服务记录线索。
- **预期结果**：页面行为与[设计文档首页验证任务](design/2026-10-24-76-execution-queue.md#可执行任务与验证)一致；日程及模板配置不变，手机线索可在电脑端看到。
- **最小回传**：回复「#76 已通过」；无需导出系统已有日志。
- **关单方式**：收到确认后，在同一轮将父任务与 #76.2–#76.6 标为 `Done`，同步总览和详情，不反向核验用户结论。

### #76.2 动作日志与积分

- **状态**：Done
- **评估**：7.2（正确性 7.2，健壮性 7.1，准确性 7.2），详见 [评估报告](eval/reports/2026-10-25-76-execution-queue-review.md)。
- **分组**：#76 今日日程的执行队列与观测
- **依赖**：现有「今日日程」，无需其他 #76 子任务。
- **背景**：只有完成与跳过状态，无法追溯开始、提前或跳转，也无法核对偏离成本。
- **方案**：基于已保存的日程顺序，当前项首次在可见页面展示时自动记录开始；在当前项保留完成、跳过、暂离等局部操作，顶部首位提供「跳转日程」下拉列表。停留在当前项无需主动标记拖延。保存不可改写的动作事件，按固定规则计算完成 +10、跳过/跳转 −3，其余动作 0。运行时跳转不改写日程项或模板。
- **验收**：每个动作留下正确事件与分数；当前项自动开始且刷新不重复记开始事件；提前完成不重复执行或扣分，重复请求不重复记分；执行偏离不改动已保存的日程配置；刷新及重启后记录保留，写入失败不显示成功。
- **AI 自动验证**：`make test`、`make build`、`make vet` 通过；日程单测覆盖提前、调序、重复动作和非法跨项完成，API 测试覆盖重复提交与持久化。
- **（用户）验收操作**：在 Dashboard 的已有四项日程中观察当前项自动计时，提前完成下一项，再从顶部首位的「跳转日程」下拉列表选择更后面的项，并刷新页面。
- **预期结果**：动作日志和积分与设计一致，已保存的日程项及模板未改变。
- **最小回传**：与其余 #76 子任务合并试跑后，回复「#76 已通过」。

### #76.3 日对账

- **状态**：Done
- **评估**：7.4（正确性 7.2，准确性 7.2，可用性 8.4），详见 [评估报告](eval/reports/2026-10-25-76-execution-queue-review.md)。
- **分组**：#76 今日日程的执行队列与观测
- **依赖**：#76.2。
- **背景**：仅靠当天记忆难以核对完成、偏离和耗时。
- **方案**：从动作事件汇总总分、完成项、偏离次数和累计计时时长；顶部「日对账」打开弹窗，标题栏提供日期选择与前后一天按钮，按所选日期展示汇总和事件。合并原两处输入为一个单行日对账备注，以日期为键独立保存，不依附日程项或事件；切换日期或关闭弹窗前自动保存未提交的修改。无日程日期仍可记录备注，旧日备注继续可读。历史旧记录缺少事件时明确标示缺口。
- **验收**：切换日期时汇总、事件和备注同步更新；无日程日期可记录备注，旧备注不丢失；旧记录不伪造耗时或积分。
- **AI 自动验证**：`go test ./internal/schedule ./internal/api` 与 `make build` 通过；单测核对积分、完成数、偏离数、耗时及旧记录缺口，API 测试核对跨日期读取、独立备注持久化与旧备注兼容。
- **（用户）验收操作**：从日程区域顶部打开「日对账」弹窗，为当天写备注，未点保存直接切到前一天；再通过日期选择器跳回当天，查看备注和汇总。
- **预期结果**：切换时备注自动保存，每个日期的汇总、事件和备注相互对应，刷新后仍可查看。
- **最小回传**：与其余 #76 子任务合并试跑后，回复「#76 已通过」。

### #76.4 停车场与维护窗口

- **状态**：Done
- **评估**：8.3（完整性 8.2，可用性 8.4，交互体验 8.1），详见 [评估报告](eval/reports/2026-10-25-76-execution-queue-review.md)。
- **分组**：#76 今日日程的执行队列与观测
- **依赖**：#76.2。
- **背景**：执行中冒出的可延期小事会反复占用注意力。
- **方案**：在日程区域顶部提供停车场入口，点击后以弹窗展示输入框与便签；点击「记下」创建黄色便签，便签横向铺排并换行。点击 ✔ 后标记处理并变为绿色，点击 × 后从停车场删除。删除只作用于便签，已有记下和处理事件仍留在日对账。用户在现有日程安排的维护时段主动打开，不新增类别或计划字段。
- **验收**：停车场在弹窗内完成记下、处理和删除，记下不改变当前项；新便签默认为黄色，颜色与处理状态刷新后保留，删除后便签不再出现，既有日对账日志不受影响。
- **AI 自动验证**：`go test ./internal/schedule ./internal/api` 与 `make build` 通过；测试覆盖空内容、重复处理、当前项不变、处理及删除持久化和历史日志保留。
- **（用户）验收操作**：执行日程时点击「记下」添加一件琐事，确认便签为黄色；点 ✔ 并刷新，随后点 × 删除，打开日对账。
- **预期结果**：便签先黄后绿，删除后消失；当前项不变，日对账仍能看到已有收纳和处理记录。
- **最小回传**：与其余 #76 子任务合并试跑后，回复「#76 已通过」。

### #76.5 应用内暂离

- **状态**：Done
- **评估**：8.1（完整性 8.2，健壮性 7.1，交互体验 8.1），详见 [评估报告](eval/reports/2026-10-25-76-execution-queue-review.md)。
- **分组**：#76 今日日程的执行队列与观测
- **依赖**：#76.2。
- **背景**：主动切走时缺少返回线索，但浏览器无法可靠检测所有外部切换。
- **方案**：点击暂离后弹出对话框；输入一句切换意图或等待 10 秒确认暂离，记录事件并在弹窗中展示原当前项与线索。弹窗仅能通过「我回来了」关闭；确认暂离后以及跨日刷新页面后继续显示，返回成功才关闭。无需系统权限，不检测外部应用切换。
- **验收**：两种暂离路径都能保留返回线索；遮罩、Esc 及普通关闭操作不能退出弹窗，刷新后仍展示暂离状态，点击「我回来了」才恢复页面。
- **AI 自动验证**：`go test ./internal/schedule ./internal/api` 与 `make build` 通过；单测覆盖暂离、返回、重复返回、跨日恢复及暂离期间禁止推进。
- **（用户）验收操作**：分别以「输入一句意图」和「留空等待 10 秒」方式暂离；尝试点击遮罩和按 Esc，刷新后点击「我回来了」。
- **预期结果**：弹窗在返回前持续显示，刷新后仍保留原当前项和返回线索；点击「我回来了」后关闭并继续执行。
- **最小回传**：与其余 #76 子任务合并试跑后，回复「#76 已通过」。

## #77 日程执行计时准确性

- **状态**：待规划
- **分组**：#76 评估衍生
- **背景**：跳转日程后原项开始时间仍有效，之后完成原项时会把处理其他项的时间一并计入；日对账累计计时可能重叠。自动开始写入失败后，当前页面也不会再次尝试记录开始。
- **影响**：当日耗时可能高估或缺失，影响 #76.2 与 #76.3 的数据可信度。
- **严重程度**：中等。
- **来源**：[验收后评估](eval/reports/2026-10-25-76-execution-queue-review.md)。

## 产品定位决策

**从**：多 Agent 会话的状态查看工具
**到**：多 Agent 会话的注意力管理与调度工具，让用户能快速判断下一步该关注哪一路 Agent。

核心 workflow：启动 Agent → 自动发现会话 → 按项目归类 → Dashboard 汇总状态 → 用户依据提醒和建议进行关注、授权或切换。

**主动不做的事**：

- 不替代 Claude Code、Hermes 或其他 Agent 的对话和执行能力。
- 不自动替用户批准高风险操作。
- 不在 Dashboard 中复制完整的 Agent 工作界面。

## 拒绝清单

- 以独立项目 ID/名称实体替代“路径即项目”模型。
- 通过抓取终端渲染内容承载所有 Agent 状态，优先使用稳定的 JSON 或明确命令输出。
- 在 pflow 内自建 WebSocket + PTY 桥接，优先复用成熟的 ttyd + tmux 链路。
