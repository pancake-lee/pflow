# pflow 决策备忘

> 经审议明确否决的方向、踩坑记录与决策变更历史。当前生效的方案写在 design/backlog 中，本文件只记录"不采纳"及理由。

## 2026-10-13 Codex 托管关联边界

- 用户明确：按首条非 `/` 开头消息的发送时刻开始寻找会话记录，首条消息之前不按启动时间猜测关联。
- 不采纳在该消息之后的小时间窗口内继续消除同目录 A/B 误判的要求，用户接受该边界；不再仅以这一残余风险扣分。
- 本轮用户选择 3A：通过既有 rollout 首条有效消息落盘触发关联，不引入终端输入拦截或新 hook；接受磁盘落盘与轮询延迟。已实现并验证，见 [backlog #61](backlog.md)。


## 2026-10-13 开发环境服务命令边界

- `make start`、`make stop`、`make status` 仅是用户开发环境的便利命令，保持当前实现。
- 用户明确不要求严谨治理这些命令的进程身份、重启和清理行为，不作为产品功能质量评分或修复任务来源。
- 撤销本轮 #40 的评估内容，删除衍生修复任务 #55 及其候选方案；#61 首条有效消息触发关联保持独立。
