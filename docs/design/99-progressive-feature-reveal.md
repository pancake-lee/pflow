## 2. 讨论背景：信任问题的引出

复习「认知卸载边界」时，用户给出的实战结论是：**互补性卸载框架在作者本人场景下执行良好，因为系统由自己从行为习惯中总结而成，信任的是「规则生成器」而非每次建议**——开发期验证过一次逻辑，运行期只需粗粒度监控（界面没乱 → 照做）。

由此暴露核心问题：**陌生用户没有这笔「信任存款」**。他们面对每个建议都得现场判断「这建议合理吗？优先级对吗？」，恰好落回工具本要解决的元认知瓶颈。知识锚点功能（展示理论依据）的初衷是「设计理念透明化」，但其深层价值应是 **trust bootstrap**——让用户低成本建立信任。

## 3. 核心思路：渐进式功能展示

- **问题**：如果第一次使用就必须理解整套设计理念才能信任并善用应用，入门门槛过高。
- **来源类比**：游戏关卡设计——给用户设计「新手状态」，让其在探索地图、人物关系、技能/数值系统的过程中逐渐上手。
- **核心机制**：刚使用工具时只呈现简单功能；体验完一个功能后，再开放进阶功能；或检测到某个操作完成后逐步开放。
- **两条落地原则**：
  - 功能展示跟随「用户当前需要」而非固定时间表（需求驱动解锁）
  - 保留「跳过过渡」入口——老用户重装系统/换新电脑时，不必重新走一遍新手流程

## 4. 与 pflow 的结合点（待探讨，非决策）

- 军情哨/提醒功能的**等级化展示**：新用户先见基础提醒（谁在等、等多久），进阶功能（提醒分数算法细节、知识锚点、主线/支线策略）随使用逐步亮出。
- **技能解锁式引导**：把「主线+2 支线策略」「保护期」「注意力遮罩」等概念做成渐进教程，每次只教一个，教完即用。
- **检测驱动的解锁**：例如用户第一次手动切换了主线 → 解锁「切换保护期」的说明；第一次忽略提醒 → 解锁「提醒分数」的解释。

## 5. 批判性审查记录（2026-09-03 讨论中提出的边界）

- **游戏 vs 工具的本质差异**：游戏可以专门开教学关，工具用户带着任务来，没耐心上课。引导必须「顺路」（嵌入任务流本身），不能主动打断。
- **渐进展示与「界面不乱」信任条件的张力**：界面随时间变化对老用户可能构成「错乱」；功能解锁时需即时亮相而非悄悄出现；军情提示不得引用用户尚未见过的功能。
- **跳过悖论**：无法让用户跳过他们看不见的东西——老手第一天就需要高级功能，按使用天数解锁会惩罚他；需提供功能总览（看得见的目录）作为兜底。
- **注意不要滑向「系统自动判断」**：微调/解锁的判定用于「展示什么」，不用于「替用户决策」，与 pflow「只展示、不判断」的立身原则保持一致。
