# 46 日程与模板 — 功能设计

## 1. 背景与目标

pflow 已经帮助用户判断多个 Agent 项目何时值得关注，但用户当天的非 Agent 工作、生活安排仍散落在外部 Markdown 时间表中。日程能力将当天的计划带回 Dashboard，让项目注意力引导和个人时间节奏在同一个视图中出现。

本功能的目标是：用户可快速以模板规划某一天，在当天只看到“现在做什么”和“接下来做什么”，并由自己确认完成或跳过。系统提示，不替用户自动推进日程。

## 2. 核心概念

- **实际日程**：某个自然日的可执行安排。它包含有序的日程项及当天的完成、跳过记录。
- **日程模板**：可复用的日程项集合，不带日期和执行记录。模板是一次性快照，修改通过“应用到编辑器，另存为新模板，删除旧模板”完成。
- **日程项**：以开始时间、内容、专注时长和 break 时长描述的一段安排。break 属于前一日程项的末段，不是独立日程项；新增日程项的默认 break 为 10 分钟。
- **末项**：可设置为从开始时间持续至当天结束，适用于没有确定时长的安排，且不设置 break。
- **自由日程**：由系统根据时间空档临时推导的展示状态，不写入计划或执行记录。

## 3. 日程编辑与模板

Dashboard 提供“日程”入口，进入同一套日程编辑界面。用户先选择日期，再编辑该日的时间轴：添加、删除、排序和填写日程项；保存后成为该日期的实际日程。

编辑器内同时提供模板下拉框和模板管理动作：

1. 选择模板并“应用”时，仅把模板内容填入当前未保存编辑器，不直接写入该日计划，也不改变模板。
2. 将当前编辑器内容保存为模板时，要求输入模板名称，生成新的模板。
3. 可删除任一模板。删除不会影响已保存的实际日程。
4. 不提供单独的模板编辑页。用户通过应用、另存和删除完成模板更新。

保存实际日程时，系统校验日程项内容、时间顺序、时段冲突、时长和 break 的合法性，并在错误位置说明原因。编辑已开始执行的当天计划时，未变更的日程项保留其执行记录；替换或删除已记录的日程项前，界面要求确认，以免无意丢失历史。

## 4. 当天 Dashboard 展示与推进

当天存在实际日程时，Dashboard 在标题栏下、筛选栏上方显示独立的“今日日程”区域，并以分割线与筛选栏明确隔开。该区域位于主线项目卡片之上，不依赖是否发现 Agent session。

区域始终只展示两项：

- **当前日程**：用户正在处理的日程项，完整清晰显示内容、时间和阶段。开始时间之前、两个日程项之间或末项之后没有待处理日程时，显示“自由日程”作为当前项。
- **下一日程**：按计划顺序的下一项。它以与项目卡片相同的渐隐机制展示，时间越接近越清晰、越值得注意。

首次进入某日时，系统依据当前时间定位当前项或自由日程。此后的计划时间流逝不会自动把当前项切换为下一项：若用户尚未处理，它会继续留在当前位，避免系统擅自替用户判断。用户在真实日程项上点击“完成”或“跳过”后，系统记录对应操作和发生时间，并将展示推进到下一项；两种操作都不删除原计划。自由日程没有完成或跳过操作。

当时间进入当前日程项的 break 末段时，当前项显示“休息中”和剩余时间，并复用项目卡片的高亮跑马灯效果。break 结束不触发自动推进，仍由用户决定何时完成或跳过该项。

## 5. 注意力表达

日程沿用项目已验证的双维度表达，而不把所有效果压缩成单一分数：

- **日程提醒分**由下一日程与当前时间的差距计算，临近开始时间逐步升高，逾时但尚未推进时保持最高提示。
- **日程迷雾分**由提醒分反向映射，提醒越强，下一日程越清晰；两者分别服务于高亮和半透明表现。
- 当前日程和自由日程始终无迷雾；当前项在 break 阶段额外获得高亮，不因而变为半透明。

这套规则不参与项目的提醒评分，也不改变专注模式或项目卡片的既有含义。两类分数只复用相同的视觉语言和映射方式。

## 6. 数据与边界

日程和模板保存在用户本机 `~/.pflow/` 下的版本化 JSON 数据中，并使用临时文件加 rename 的原子写入方式。实际日程、模板定义和当天的执行记录属于同一领域数据，但模板永远不携带实际执行状态。读写错误需要返回可诊断信息，不能静默丢弃或覆盖已有用户数据。

开发交付时，若本机尚无当天实际日程，将用户在本次需求中提供的日程写入**本机用户数据**，使 Dashboard 可立即展示；该日程内容不写入设计文档、测试夹具、源码或任何提交仓库的文件。已有同日期数据绝不覆盖。

本阶段不包括跨设备同步、循环日程、日历同步、提醒推送或自动执行日程操作。

## 7. 验收标准

- 用户能在一个编辑界面保存任意日期的实际日程，新增日程项默认 break 为 10 分钟；模板可增加、删除和应用，应用不会直接覆盖已保存的日程。
- 已保存的当天日程在标题栏下、筛选栏上方出现，并且只显示当前项和下一项；无日程、首尾空档和中间空档均正确显示自由日程。
- 首次时间定位有效，但时间流逝不会自动推进；完成与跳过都留下记录并仅在用户操作后推进。
- 下一项的透明度与临近程度一致，当前项始终清晰；进入 break 后出现高亮跑马灯和休息状态。
- 开发交付时，本机在不存在当天数据的情况下可直接展示用户提供的日程，且已有数据不会被初始化逻辑覆盖；该数据不进入仓库。
- JSON 数据可跨服务重启保留，非法时间轴和写入失败可被诊断，自动化测试、静态检查及前端构建通过。
