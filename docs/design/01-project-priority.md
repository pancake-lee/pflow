## pflow Dashboard 重构：以项目为维度的任务管理

> 已经完成，可能已过时，不再更新

### 一、设计目标

- **视图升级**：从“扁平 session 列表”变为“项目 → session”两级结构。
- **任务策略**：用户可设定 **1 个主线项目**、**最多 3 个支线项目**，其余为普通项目。
- **兼容现有数据**：支持已有的本地 Agent 会话（Claude Code、Hermes）和 Web AI 会话，并能将它们归类到同一个项目下。

### 二、核心概念定义

| 概念 | 说明 | 示例 |
|------|------|------|
| **项目 (Project)** | 用户要进行的工作单元，可包含多个 AI 会话 | `pflow`、`hermes`、`周报` |
| **主线项目 (Primary)** | 今日最高优先级，只能有 1 个 | `pflow` |
| **支线项目 (Secondary)** | 今日次优先级，最多 3 个 | `周报`、`学习 Rust`、`代码审查` |
| **普通项目 (Normal)** | 其他需要关注但不紧急的项目 | - |
| **归档项目 (Archived)** | 已完成或暂时忽略，可折叠 | - |

### 三、数据模型调整

需要新增 `projects` 存储和 session 与 project 的关联。

#### 3.1 后端数据结构

```json
// ~/.pflow/projects.json
{
  "projects": [
    {
      "id": "proj-1",
      "name": "pflow",
      "path": "/home/user/pflow",           // 可选，本地项目路径
      "priority": "primary",                // primary | secondary | normal | archived
      "createdAt": "2025-06-13T00:00:00Z",
      "order": 0                            // 手动排序优先级
    }
  ]
}

// session 数据扩展（已有 sessions.json）
{
  "sessionId": "claude-xxx",
  "type": "claude",
  "projectId": "proj-1",                   // 关联项目ID（新增）
  // ... 原有字段
}
```

#### 3.2 前端状态管理

- Vuex/Pinia store 中维护 `projects` 和 `sessions`，通过 `projectId` 关联。
- 计算属性：`projectWithSessions` 将 sessions 分组到 project 下，未关联 project 的 session 放入“未分类”项目。

#### 4.2 交互说明

| 元素 | 操作 | 行为 |
|------|------|------|
| **主线项目区域** | 只有一个项目，不可直接添加，需通过其他项目的“设为主线”触发 | 原主线自动降级为普通 |
| **支线项目区域** | 最多显示 3 个，超出时需将某个支线改为普通才能添加新的 | 拖拽排序（可选） |
| **普通项目区域** | 可折叠，显示数量徽章 | 可通过右键菜单或按钮“设为支线” |
| **每个项目卡片** | 显示项目名、优先级标记、操作按钮（切换主线/支线/普通/归档） | 内部 session 列表显示状态点（🟢🟡🔴）和最后活动时间 |
| **session 行** | 显示 session 类型图标、状态、最后消息摘要（可选）、操作按钮（终端/打开） | 点击终端按钮打开 ttyd 页面或浏览器标签 |

#### 4.3 优先级切换规则

- **设为主线**：当前主线降为普通，该项目升为主线。
- **设为支线**：若当前支线数 <3，直接加入；若已达3，提示“请先移除一个支线项目”。
- **设为普通**：从主线/支线移除，放入普通区域。
- **归档**：移入归档区域，默认折叠；可恢复为普通。

### 五、实现计划（增量开发）

#### 阶段一：数据层调整
1. 创建 `projects.json` 文件结构和读写函数。
2. 修改 session 存储，增加 `projectId` 字段（兼容旧数据：未指定 projectId 的 session 归入“未分类”项目）。
3. 提供迁移脚本：自动将现有 session 按工作目录（对本地 Agent）或域名（对 Web AI）归类到同名项目，或全部放入“未分类”。

#### 阶段二：前端视图重构
1. 修改 Dashboard API 返回 `/api/dashboard` 时同时返回 projects 和 sessions。
2. 前端 store 添加 projects 模块，实现 `groupSessionsByProject` 计算属性。
3. 重新设计 Vue 组件：
   - `ProjectCard.vue`：展示项目及其 session 列表
   - `PrioritySelector.vue`：切换优先级的按钮/菜单
   - `SessionRow.vue`：复用现有 session 行样式
4. 实现拖拽排序（可选，可用 `vuedraggable` 简化）。

#### 阶段三：策略与视觉优化
1. 主线/支线数量校验，前端+后端双重检查（防止并发修改）。
2. 本地存储用户的项目顺序和折叠状态。
3. 添加简单的帮助提示（tooltip）说明主线/支线规则。

### 六、技术风险与应对

| 风险 | 概率 | 应对 |
|------|------|------|
| 一个项目下 session 过多导致 UI 卡顿 | 低 | 分页或虚拟滚动（初期可限制显示最近5个，点击“更多”展开） |
| 优先级状态同步冲突（多设备） | 低 | 后端存储所有状态，前端 WebSocket 实时更新 |
| 用户误操作将主线移除 | 中 | 提供“撤销” Toast 提示（5秒内恢复） |

### 七、总结

本方案将 pflow 从“会话列表”升级为“项目驱动的任务看板”，与“1主线+3支线”策略深度绑定。实现上增量修改现有代码，不破坏已有功能。用户可自然过渡，也可以立即利用新特性提高每日工作效率。这是 pflow 从监控工具向“AI 任务调度中心”演进的重要一步。
