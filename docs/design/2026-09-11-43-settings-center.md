# #43 设置中心 — 功能设计

> 本文档描述 pflow 将用户可调整的运行偏好集中到设置中心的设计；它不是开发任务清单，实施拆分见 [backlog #43](../backlog.md#43-设置中心与项目管理迁入)。

## 1. 背景与目标

目前 pflow 的项目策略可以在 Dashboard 中操作，但扫描范围、刷新频率、专注时长、提醒算法和视觉强度等可调整行为散落在命令参数或前端、后端常量中。用户无法从产品界面了解这些选择，也无法在不改源码的情况下让 pflow 符合自己的工作习惯。

本需求建立一个统一的设置中心，目标是：

- 让已实现功能中会影响用户工作流的偏好有唯一、可发现的修改入口。
- 将现有“项目管理”保留为项目策略能力，但在信息架构上归入设置中心。
- 让每项配置显示其效果、默认值和恢复默认入口；修改后即时生效并跨重启保留。
- 为通知、换肤等后续功能预留一致的设置接入方式，但不展示尚未可用的空白页面。

不把调试覆盖、解析兼容参数、内部算法实现系数和不可由用户判断效果的工程常量包装成普通设置。它们继续作为开发实现细节；若未来证明需要用户调节，应先设计其用户语义和安全边界。

## 2. 信息架构与布局

Dashboard 顶栏的“项目”按钮替换为“设置”入口。进入后保留 pflow 顶栏和返回 Dashboard 的明确入口，主体采用窄侧栏加内容区：

- **通用与显示**：控制 Dashboard 的会话扫描范围、闲置会话显示上限、Agent 筛选、自动刷新频率，以及每日引导是否在当天首次打开时出现。
- **注意力与专注**：控制提醒的可感知策略，包括无显式专注时的保护时长、每次“专注 +”增加的时长、提醒敏感度与遮罩强度。普通用户看到的是带效果文案的预设；展开“精细调整”后才能调节已被确认具有明确用户语义的各项数值。
- **时间估算**：将“每条消息折算的活跃时间”和无消息时的保守估算比例放在高级区，展示其只影响估算展示和建议依据、不改变原始会话记录的说明。
- **项目管理**：现有项目根、主线和两个支线槽位的完整管理界面，保留添加、移除、重新分配和空槽引导。Dashboard 卡片仍可执行快捷设为主线/支线等高频动作；设置页是全量管理入口。

分类只展示至少含有一个可用设置的项目。未来桌面通知、主动推送、换肤、跨设备等功能完成时，各自在此注册相应分类或归属到现有分类；功能未启用、浏览器不支持或无权限时，分类内说明原因并提供所需动作，而不是静默失效。

## 3. 交互与反馈

用户在每项设置旁先看到“这会改变什么”，再看到控件、当前值和默认值。枚举型偏好使用少量有语义的选项；连续数值使用受限输入与单位；高影响或难理解的参数收进高级区。每个分类都有“恢复本分类默认值”，单项也可恢复默认；恢复前显示受影响项，避免误清除项目策略。

常规改动在通过本地校验后立即保存，并在控件旁显示“已保存”或具体校验失败原因；无需单独的全局保存按钮。影响正在运行体验的配置即时应用：例如刷新节奏重新调度、专注增量影响下一次点击、遮罩强度立即预览。已有专注计时不因修改增量而回溯改变。

当用户从 Dashboard 触发项目快捷操作时，结果仍即时反映在项目管理页；当设置页更改显示或扫描偏好时，返回 Dashboard 后使用同一份偏好。页面加载失败或保存失败必须明确展示错误与重试入口，不能假装配置已生效。

## 4. 配置边界与持久化

设置中心按三种所有权保存偏好：

- **设备级运行偏好**：影响扫描、注意力、时间估算和每日引导的设置，由本机 pflow 配置持久化，服务端读取并校验后用于 CLI/Dashboard 的共同运行逻辑。
- **浏览器视图偏好**：仅影响当前浏览器的折叠状态、临时筛选和页面布局的选择，继续由浏览器本地保存，不把它们误当成跨环境的运行策略。
- **项目策略**：项目根和槽位仍保持现有独立、原子写入的项目数据，避免把频繁变更的项目列表与通用偏好互相覆盖；它在产品信息架构中是“设置的子配置”，不意味着必须合并物理文件。

首次启用时从当前行为生成默认设置，保证升级前后的 Dashboard 行为不变。旧项目策略无需迁移；缺失设置文件时安全使用默认值。保存采用版本化、原子替换和范围校验，并对未知字段保留兼容性。配置中心 API 只返回和接受用户设置，不返回 Agent 对话、密钥或本机无关的诊断数据。

## 5. 关键决策

- **设置中心而非内联调参的替代品**：设置中心提供完整、可回看的总览；高频且上下文明确的提醒参数，后续仍可在军情提示旁提供内联快捷微调，两者共享同一设置和默认值。
- **语义优先、精细调整后置**：先用“更早提醒/平衡/更少打扰”等可理解的控制表达意图，再让需要精确控制的用户展开数值。这样响应既有“参数应可参与调整”的诉求，也避免把算法系数直接变成参数墙。
- **项目管理在设置中、快捷操作留在 Dashboard**：项目配置是低频的全局管理；卡片上的主线/支线调整是工作流内的高频动作，移除会增加切换成本。
- **未实现功能不预埋表单**：通知阈值、推送渠道、皮肤资源和同步授权等必须随所属功能的真实能力、权限状态和验收标准一起设计，不能先保存没有效果的设置。

## 6. 验收标准

- 用户能从 Dashboard 进入设置中心并返回，不再需要独立的顶栏项目管理入口。
- 已实现、具有用户语义的运行偏好都能查看说明、修改、恢复默认并跨服务重启保持；默认升级行为与改造前一致。
- 项目根与主线/支线槽位可在“项目管理”子配置中完整管理，Dashboard 快捷操作与该页双向一致。
- 非法值、保存失败和不支持的功能状态都有可见且可行动的反馈；项目策略和通用偏好均不会因写入中断而损坏。
- 通用配置、项目配置和相关 HTTP 边界具备自动化测试；前端完成构建与类型检查。
