# pflow 功能设计文档：每日引导（Daily Boot）

> 本文档描述 pflow 的 **“每日引导”** 功能——一套在工作日开始前执行的认知开机引导程序，用于帮助用户完成认知卸载、模式切换与目标锚定，再进入核心战局视图。

## 1. 功能定位

### 1.1 名称与命名讨论

功能暂定名为 **Daily Boot**（每日引导），备选方案：

| 名称 | 含义 | 适用性 |
|------|------|--------|
| **Daily Boot** ✅ | 每日引导/每日启动 | 中性、简洁，强调“启动”属性 |
| Morning Rollcall | 早间点卯 | 贴合军帐隐喻，但“点卯”带强制感，容易误导用户认为这是必须完成的任务 |
| Daily Ritual | 每日仪式 | 准确描述了功能本质，但“仪式”一词可能被误解为形式主义或玄学 |

**建议采用 `daily-boot`**，理由：
- “Boot”在计算机语境下天然关联“启动/引导”，对开发者用户而言直觉清晰。
- 与 `pflow serve`、`pflow status` 等命令风格一致，可扩展为 `pflow daily-boot` 或内嵌在 Dashboard 启动流程中。
- 避免“仪式”等词可能带来的心理抗拒。

### 1.2 功能边界

| 做 | 不做 |
|---|---|
| 引导用户完成认知卸载 | 接管用户的待办列表或任务管理 |
| 帮助用户锚定今日唯一的硬边界目标 | 量化/拆解用户的目标 |
| 通过手动复选框帮助用户完成模式切换 | 强制锁屏或阻止用户跳过流程 |
| 在 Dashboard 上展示目标以强化记忆 | 替代用户的 Jira/Todoist/项目管理工具 |

### 1.3 设计原则

- **非侵入**：不弹窗、不警报、不制造焦虑感
- **可跳过**：用户随时可以选择跳过引导直接进入 Dashboard
- **无感**：引导本身不是“任务”，只是“入口”
- **信息层**：pflow 只呈现信息，不做自动跳转或代劳

## 2. 触发时机与入口

### 2.1 触发条件

`daily-boot` 在以下条件**同时满足**时触发：

1. `pflow serve` 启动后，检测到当天尚未完成引导（以日期为粒度标记完成状态，非以会话为粒度）。
2. Dashboard 首次加载。

### 2.2 触发后行为

- 首次加载时自动展示引导流程（三幕），而非直接显示主 Dashboard。
- 引导完成后，当日后续刷新/重载不再重复展示，直接进入主 Dashboard。
- 提供显式的 **“跳过引导 →”** 入口（位于界面右下角，低调但不隐藏），跳过即视为当日已完成，直接进入 Dashboard。

### 2.3 存储标记

- 引导完成状态存储在 `~/.pflow/state.json` 中，结构为 `{"daily_boot": {"2026-06-26": true}}`。
- 仅记录日期，不记录完成时间点。

## 3. 三幕交互流程

### 3.1 全局布局

- 三幕共享同一容器，幕间切换为**平滑淡入淡出**（约 300ms）。
- 所有文案使用中性、无催促感的语气。第一、二幕的背景色为暖白/极淡灰，区别于第三幕主 Dashboard 的冷色背景，以视觉暗示“这是预热区”。

### 3.2 第一幕：启动热身（Boot）

**功能目标**：提供认知卸载窗口 + 锚定今日唯一目标

**界面构成**：

| 元素 | 内容 | 说明 |
|------|------|------|
| 顶部问候 | “早安。” 或 “军帐已开。” | 简洁，不带感叹号 |
| 引导文案 | “先花些时间清理杂务，为今日定调。” | 提示用户处理邮件/消息/琐事，不做强制说明 |
| 目标输入框 | 占位符文案：“**今天只有一件事：**” | 单行输入框，无字数限制，回车或点击“下一步”即保存 |
| 时间感知标尺 | 底部一条淡蓝色细线进度条（从 0% 缓慢填充至 100%） | 持续时长默认 30 分钟，可配置但非 UI 重点。进度条走完后仅做背景色温微变（冷白→暖黄），不弹出任何提示。进度条允许用户拖动查看已过去的时间，但不能重置或加速 |
| 下一步入口 | “我已处理完杂务，确定今日目标 →” | 文字链接而非按钮，降低“完成感”的权重，避免用户将“完成热身”视作成就 |

**交互规格**：

- 进度条**不显示数字倒计时**（如“还剩 15:32”），只显示进度百分比或纯图形进度。
- 用户可在热身窗口内随时填写目标，也可留空。留空时“下一步”仍可点击，但在第三幕主线卡片上不展示目标句。
- 用户可在热身窗口内自由切换浏览器标签/应用去处理邮件等杂务，pflow 不检测用户是否“真的在热身”。

**设计依据**：用“存量视角”（过去了多少）替代“损失视角”（还剩多少），避免倒计时引发的焦虑。进度条填满后只做视觉微变，符合“提醒即觉察，而非警报”的原则。

---

### 3.3 第二幕：切换仪式（Ritual）

**功能目标**：通过物理动作 + 手动确认，完成模式切换

**界面构成**：

| 元素 | 内容 | 说明 |
|------|------|------|
| 引导文案 | “亲赴前线前，检查行装。” | 可硬编码，暂不做配置 |
| 复选框 1 | ☐ **我已倒好一杯水/咖啡，放在手边。** | 完成时态陈述句 |
| 复选框 2 | ☐ **我已打开主线任务所需的全部窗口。** | 完成时态陈述句 |
| 复选框 3 | ☐ **我已关闭微信、企微及其他无关应用。** | 完成时态陈述句 |
| 确认按钮 | “确认，进入战局 →” | 三个复选框全部勾选后才亮起。未全部勾选时为置灰状态，hover 时显示提示“请先完成三项准备” |
| 底部跳过入口 | “直接进入 Dashboard” | 低调文本链接，位于左下角。点击后跳过仪式，当日不再重复展示 |

**交互规格**：

- 复选框**必须手动点击**，不支持键盘快捷键勾选（防止用户无意识快速点击通过）。
- 点击复选框时提供一个微弱的“咔哒”反馈动画（复选框本身被打勾的拟物动画）。
- 三个复选框不设顺序限制，用户可以任意顺序勾选。
- 确认按钮点击后，播放一个“卡片折叠消失”的转场动画（约 400ms），然后平滑过渡到第三幕。

**设计依据**：手动点击复选框的动作，配合完成时态的陈述句，让本体感受参与“模式切换”宣告。这是实施意图的落地——把抽象意图（我要专注）绑定到具体情境（当我看到这三个勾时）。

---

### 3.4 第三幕：核心战局（Dashboard）

**功能目标**：展示主线/支线项目 + 当日目标锚点

**界面构成**：

Daily Boot 完成后的主界面即 pflow 现有 Dashboard，需新增以下元素：

| 新增元素 | 位置 | 规格 |
|----------|------|------|
| **当日目标句** | 主线项目卡片顶部（项目名称上方） | 字号比项目名称略大（如 18px vs 16px），常规字重，不加“目标：”或“KPI：”等前缀标签。如果第一幕未填写，则不展示该区域 |
| **目标编辑入口** | 目标句右侧（hover 时出现） | “✎”图标，点击后目标句变为可编辑输入框，失焦即保存。不新增独立编辑页面 |

**交互规格**：

- 目标句仅做展示用途，不参与任何提醒分数计算或自动化逻辑。
- 目标句修改后立即保存至 `~/.pflow/state.json`。
- 目标句在刷新页面后仍保留，直至次日首次引导时被新目标覆盖（或用户手动清空）。

## 4. 数据结构

### 4.1 存储文件：`~/.pflow/state.json`

```
{
  "daily_boot": {
    "2026-06-26": {
      "completed": true,
      "goal": "完成支付模块的接口联调，下班前给老板看"
    }
  }
}
```

- `completed`：当天是否已完成引导（含跳过）。
- `goal`：当天填写的目标句，可为空字符串。

### 4.2 里程碑节点

| 阶段 | 目标 | 状态 |
|------|------|------|
| M1 | 三幕 UI 静态还原（Vue 组件） | 待开发 |
| M2 | 幕间切换动画 + 进度条逻辑 | 待开发 |
| M3 | 复选框交互 + 确认逻辑 | 待开发 |
| M4 | 状态持久化（读写 `~/.pflow/state.json`） | 待开发 |
| M5 | 与主 Dashboard 路由打通，实现“首次加载触发展示，当日后续加载直接进入 Dashboard” | 待开发 |
| M6 | 目标句在 Dashboard 主线卡片上的展示与编辑 | 待开发 |

## 5. 界面原型描述

> 以下为纯文字原型描述，开发时可直接作为 UI 规格参考。

### 5.1 第一幕：启动热身

```
┌──────────────────────────────────────────────────────────────┐
│                                                            │
│                     早安。                                   │
│             先花些时间清理杂务，为今日定调。                  │
│                                                            │
│         ┌──────────────────────────────────┐                │
│         │  今天只有一件事：                │                │
│         │  [输入框，占位符如上]            │                │
│         └──────────────────────────────────┘                │
│                                                            │
│                                  我已处理完杂务，确定今日目标 →│
│                                                            │
│  ████████████░░░░░░░░░░░░░░░░░░░░░░░░░░  68%  ▏ 跳过引导 → │
│  └────────────────────────────────────────┘                 │
│                                                            │
└──────────────────────────────────────────────────────────────┘
```

- 进度条位于底部，颜色为淡蓝 `#8BB8D6`。
- “跳过引导 →” 位于右下角，字体颜色为灰色 `#999`，hover 时变深。

### 5.2 第二幕：切换仪式

```
┌──────────────────────────────────────────────────────────────┐
│                                                            │
│                  亲赴前线前，检查行装。                       │
│                                                            │
│         ☐ 我已倒好一杯水/咖啡，放在手边。                    │
│         ☐ 我已打开主线任务所需的全部窗口。                    │
│         ☐ 我已关闭微信、企微及其他无关应用。                  │
│                                                            │
│                                  [  确认，进入战局 →  ]      │
│                                                            │
│  直接进入 Dashboard                                         │
│                                                            │
└──────────────────────────────────────────────────────────────┘
```

- 复选框使用原生 `<input type="checkbox">` 或 Vue 自定义组件，勾选时做拟物点击反馈。
- 确认按钮初始为置灰（`disabled`），三个全勾后变为可点击（主色 `#4A90D9`）。

### 5.3 第三幕：主线卡片（目标句展示）

```
┌─────────────────────────────────────────────┐
│  ⭐ 主线项目                                  │
│  ┌─────────────────────────────────────────┐ │
│  │  ★ 完成支付模块的接口联调              │ │  ← 目标句，18px
│  │  🚀 pflow                              │ │  ← 项目名称，16px
│  │    ├─ [🟢] claude (c50e1b2e)          │ │
│  │    └─ [⚪] claude (a3b2c1d4)          │ │
│  └─────────────────────────────────────────┘ │
└─────────────────────────────────────────────┘
```

- 目标句前加一个极淡的星标 `★` 或 `·` 作为视觉锚点，不加“目标：”文字标签。
- hover 卡片时目标句右侧出现“✎”编辑图标。
