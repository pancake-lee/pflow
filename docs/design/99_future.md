# Future：以后再考虑的功能点

> 状态：暂缓，2026-10-23 从 backlog 迁入。以下内容尚未排期；启动开发时先在 [backlog](../backlog.md) 建立任务并重新规划。已有较完整方案的 #23、#24 分别保存在独立的 `99-` 设计文档。

## #19 桌面通知

- **状态**：暂缓
- **分组**：注意力通知
- **背景**：当前提醒分数只在 Dashboard 中展示，用户离开页面后无法及时获知需要关注的项目。
- **分析**：浏览器 Notification API 可以补足页面外提醒，但需要处理权限、阈值、重复通知和用户拒绝等状态。
- **方案**：待规划。方案应定义通知触发、去重、权限管理和用户可控边界，并与现有提醒分数保持一致。
- **验收**：通知权限、阈值触发、重复通知抑制和权限拒绝均有明确行为。

## #20 行动建议主动推送

- **状态**：暂缓
- **分组**：注意力通知
- **背景**：当前行动建议主要随 Dashboard 请求生成，后台没有持续主动推送能力。
- **分析**：主动推送依赖后台守护进程和可靠推送通道，需要明确服务生命周期、推送时机和失败重试边界。
- **方案**：待规划。方案应定义后台计算、推送通道、消息去重和用户关闭策略。
- **依赖**：需要后台守护进程和可靠的推送通道。
- **验收**：服务在无页面主动刷新时仍能按规则推送，并能查看推送原因和时间。

## #21 统帅偏好学习

- **状态**：暂缓
- **分组**：注意力通知
- **背景**：当前提醒频率由固定规则决定，没有利用用户响应和忽略行为调整提醒策略。
- **分析**：偏好学习需要区分用户主动忽略、已处理和暂时离开等行为，避免学习结果突破用户设定的通知边界。
- **方案**：待规划。方案应定义反馈信号、偏好模型、可解释性、重置方式和安全边界。
- **验收**：偏好数据可解释、可重置，学习结果不会突破用户设定的通知边界。

## #25 跨设备同步

- **状态**：暂缓
- **分组**：平台扩展
- **背景**：当前 Dashboard 面向本机浏览器，没有手机或平板查看会话状态及执行批准操作的能力。
- **分析**：跨设备能力涉及身份认证、状态同步、远程授权和断线恢复，安全边界高于普通只读展示。
- **方案**：待规划。方案应先明确设备身份、同步范围、授权确认和离线行为。
- **验收**：跨设备身份、状态同步、授权安全和离线/断线行为有明确方案。

## #55 Future：本地与多远端会话融合

- **状态**：暂缓
- **分组**：平台扩展
- **背景**：用户要求未来同时接入本地 Agent 会话及多个 HTTP 远端 pflow serve，在同一 Dashboard 合并、融合展示。
- **方案**：Future 方向已确认，具体实现留待独立规划。为本地与每个远端建立稳定数据源身份，各源独立采集，统一会话状态后汇聚展示，保留来源标识和操作归属；可按来源查看，也可按用户确认的跨源项目映射融合。
- **分析**：会话唯一性需包含来源，不能仅按 session ID 去重；不同机器相同路径不自动视为同项目，同一会话被多个源读取时需定义去重规则。融合后的注意力评分、时间累计、项目策略及日程归属需要明确，不能直接相加远端分数。单源离线不阻塞其他源，标明数据新鲜度。连接凭据、认证与版本兼容随正式规划确定。
- **任务列表**：
  - [ ] 确认本地 Agent 支持范围和本地采集方式。
  - [ ] 规划多远端管理、来源身份、独立连接状态与版本兼容。
  - [ ] 规划会话去重、跨源项目映射、时间与评分融合。
  - [ ] 规划融合展示、来源筛选及编辑操作的目标服务归属。
- **验收**：本地与至少两个远端同时展示；同名路径和同 ID 不误合并；可追溯会话来源；单源离线不影响其他源；融合与编辑归属规则可解释并有验证。
