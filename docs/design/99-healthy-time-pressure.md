## 2. 知识内容记录

### 2.1 核心概念：帕金森定律

任务给的时间越充足，越容易拖到最后才完成，工作会膨胀填满所有可用时间。
讨论中的反向利用思路是：通过**刻意压缩时间窗口**制造"健康的时间压力"，以此提高产出质量，而不是制造赶工质量。

### 2.2 方法论：三层组合对抗帕金森定律

1. **2 分钟法则**：小于 2 分钟的事立刻做，不列入清单。
2. **时间盒（Timeboxing）**：给每项任务分配固定的、不可随意延长的时间段（如 9:00-10:30 写报告）。
3. **番茄钟**：专注类工作用 25 分钟工作 + 5 分钟休息，作为标准时间盒的填充单元。

一句话流程：用 2 分钟扫清杂事，把剩余任务放进时间盒，用番茄钟执行盒内专注，时间盒到点即停，剩余任务移至下个盒子。

### 2.3 概念辨析（来源讨论中的可选方向）

- **时间盒 vs 番茄钟**：前者是"限制时间"，后者是"分割时间"，适合的任务类型可能不同。
- **AI 做 Timeboxing 助理**：让 AI 估算任务耗时、设 deadline、自动提醒超限。
- **2 分钟法则 vs 帕金森定律**：什么事适合立即做，什么事适合压缩时间窗，两者互补。

## 3. 为什么想融合进 pflow

我目前的看法是，这套知识和 pflow 的产品定位有天然的贴合点：

- pflow 做的是多 Agent 会话的**注意力管理与调度**，本质上是"在有限时间窗口内决定关注哪一路"。注意力本身就是稀缺资源，帕金森定律描述的膨胀效应同样会发生在"照看 Agent"这件事上：一个会话盯太久，其他会话被冷落。
- pflow 已有若干可承载"时间压力"概念的既有机制（见下节），融合不需要从零开始。
- Daily Boot 已锚定"今日唯一硬边界目标"，时间盒可以看作目标之下的执行层结构。

## 4. 可能的融合切入点（待探讨，非决策）

以下仅为初步联想，均未做取舍，留给后续规划模式逐个评估：

- **会话/项目级时间盒**：为某路 Agent 或某个项目设定关注时间窗口，超限时反映到提醒分数或军情哨，形成"到点即停"的约束。
- **反向帕金森调度**：提醒与建议不只按"谁最需要关注"排序，也按"压缩关注窗口能带来更高产出"的思路设计，鼓励短促高频的介入而非长时间盯守。
- **2 分钟法则分级**：提醒体系区分"2 分钟内可完成的小介入"（快速批准、瞄一眼结果）与"需要整块时间的深度介入"，低成本项提示立即处理，避免堆积。
- **时间感知的视觉延伸**：Daily Boot 第一幕的"时间感知标尺"（30 分钟进度条）可以延伸为时间盒的可视化语言，让用户对窗口流逝保持无焦虑的感知。
- **AI Timeboxing 助理**：pflow 掌握各会话的历史活跃时长（见 `09-active-time-calculation.md`），有条件基于真实数据估算"这路 Agent 大概需要盯多久"，给出时间盒建议。
