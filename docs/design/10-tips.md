# pflow 功能设计文档：知识锚点（Knowledge Anchor）

**文档版本**：v1.0  
**关联阶段**：阶段四（智能调度）— 体验层增强  
**依赖模块**：军情哨（`pflow suggest`）  
**设计状态**：实现中（2026-06-25）
**实际实现**：Scenario ID 从文档概念落地为代码字段（`Suggestion.ScenarioID`），映射关系保持与本文档 §5 一致。


## 1. 功能概述

### 1.1 功能定位

知识锚点是 pflow Dashboard 右下角的**轻量级认知信息卡片**。它不参与主交互路径，不打断用户操作流，以“瞥一眼即知”的方式，将认知科学理论、产品设计理念与当前军情建议进行弱关联展示。

**一句话定义**：在用户收到军情建议的同时，右下角自动展示“为什么这么建议”的理论依据与设计逻辑。

### 1.2 设计目标

| 目标 | 说明 |
|------|------|
| **理念透明化** | 让用户感知 pflow 的每个调度决策都有科学依据，建立工具信任 |
| **知识传递** | 在不增加认知负担的前提下，向用户传递认知科学相关知识 |
| **零干扰** | 信息展示不打断主操作流，不要求用户点击、关闭或确认 |
| **上下文相关** | 展示内容跟随当前军情自动切换，保持相关性 |

### 1.3 设计原则

- **被动展示，无需交互**：用户不需要点击任何东西就能看到内容；也不提供关闭按钮（避免增加决策负担）。
- **平滑轮播，静默切换**：内容切换使用淡入淡出动画（300-500ms），不产生闪烁感。
- **弱关联，非强绑定**：知识锚点跟随军情最高优先级建议切换，但用户无需理解这种关联也能正常使用 pflow。
- **兜底机制**：当无军情建议或建议无匹配知识时，展示通用知识内容，不留下空白。


## 2. 交互设计

### 2.1 位置与布局

- **固定位置**：Dashboard 页面**右下角**，距离底部和右侧边缘各 24px。
- **尺寸**：宽度 320px，高度自适应（最小 80px，最大 160px，超出滚动）。
- **层级**：`z-index: 100`，悬浮于所有项目卡片之上，但不遮挡核心操作区（项目卡片、策略设置等）。
- **背景**：半透明毛玻璃效果（`background: rgba(15, 23, 42, 0.75); backdrop-filter: blur(8px);`），边框 1px 半透明。

### 2.2 显示状态

| 状态 | 说明 | 视觉表现 |
|------|------|----------|
| **默认态（轮播）** | 无高优军情或用户未与军情交互时，自动轮播通用知识 | 内容淡入淡出，每 15 秒切换一条，右上角显示 ⏸ 暂停按钮（悬停出现） |
| **关联态（跟随军情）** | 军情哨存在高优建议（`priority >= 3`）时，锚点自动切换至对应知识 | 切换动画从右向左滑入，右上角显示 `📡 关联军情` 小标签 |
| **悬停态** | 用户鼠标悬停于锚点卡片上方时 | 暂停轮播；背景透明度略微加深；内容区域显示“上/下”翻页箭头（允许手动翻阅） |
| **无内容态** | 无任何可展示的知识条目（极少发生） | 显示简约占位文案，保持卡片存在，不消失 |

### 2.3 切换逻辑

```
军情哨刷新（每次轮询 / 用户手动触发）
    ↓
获取最高优先级建议（取 priority 值最大者）
    ↓
读取该建议的 scenario_id
    ↓
查询知识锚点映射表，匹配对应的 knowledge_tip_id
    ↓
有匹配 → 锚点切换为匹配的知识内容（淡入淡出动画）
无匹配 → 锚点切换为通用轮播知识（随机选取一条）
    ↓
15 秒后如果军情状态未变 → 锚点保持当前内容（不重新轮播），避免频繁变化
```

**关键规则**：
- 军情变化时立即切换（优先级高于轮播定时器）；
- 军情未变时，锚点内容保持不变（不触发“每 15 秒强制刷新”），避免用户正在阅读时被切走；
- 如果用户手动翻页，暂停自动切换 30 秒，之后恢复。

### 2.4 内容结构

每条知识锚点包含以下字段，在 UI 中按此布局展示：

```
┌─────────────────────────────────────────────┐
│  📡 关联军情          [⏸] [▶]  1/3        │  ← 头部：关联状态标签 + 控制
├─────────────────────────────────────────────┤
│  🧠 注意力残留                             │  ← 理论名称（标题）
│  当前任务中断后，上下文会在脑中残留长达    │  ← 理论依据（1-2 句话）
│  15 分钟，重启需额外消耗 30%-40% 能量。   │
│  ⚙️ pflow 设计                            │  ← 设计映射（1 句话）
│  主线保护期 15 分钟不推送干扰，正是为了    │
│  尊重这一能耗规律。                        │
│  📖 了解更多 →                            │  ← 可选：展开详情链接（暂不实现）
└─────────────────────────────────────────────┘
```

**头部控制区**（悬停时显示）：
- 左：关联状态标签（`📡 关联军情` 或 `📖 知识库`）
- 中：（留空）
- 右：暂停/播放按钮（⏸/▶）+ 页码（如 1/3）

**内容区**（核心）：
- 理论名称：加粗，字号 14px
- 理论依据：字号 13px，颜色略浅
- 设计映射：字号 13px，前带 ⚙️ 图标，颜色使用品牌蓝
- “了解更多”：暂为视觉占位，点击无功能（预留扩展）

> **注**：“了解更多”链接暂不实现跳转。预留此位置是为了远期可能的扩展（如跳转至设计文档或博客文章）。


## 3. 数据模型

### 3.1 知识条目（Knowledge Tip）

```typescript
interface KnowledgeTip {
  id: string;                    // 唯一标识，如 "kt_attention_residue"
  title: string;                 // 理论名称，如 "注意力残留"
  theory: string;                // 理论依据（1-2 句）
  design: string;                // 设计映射（1 句）
  related_scenarios: string[];   // 关联的军情场景 ID 列表
  tags?: string[];               // 可选标签，如 ["认知科学", "切换成本"]
  weight?: number;               // 轮播权重，默认 1
}
```

### 3.2 军情场景（Suggest Scenario）

已有数据模型（引用自 `pflow suggest` 设计文档），知识锚点只依赖其中的 `scenario_id` 字段：

```typescript
interface SuggestScenario {
  id: string;                    // 如 "scenario_001"
  priority: 1-5;                 // 优先级
  level: "🔴" | "🟡" | "🔵" | "⚪" | "✅" | "⚠️" | "🎉";
  template: string;              // 建议文案模板
  // ... 其他字段
}
```

### 3.3 映射关系

通过 `KnowledgeTip.related_scenarios` 建立多对多关系：一条知识可以关联多个军情场景，一个军情场景也可以对应多条知识（取第一条作为主要匹配）。


## 4. Tips 内容列表（完整）

共 **12 条**知识锚点内容，覆盖军情哨 15 个核心场景 + 通用轮播。

### 4.1 注意力残留与认知惰性

**ID**: `kt_attention_residue`  
**标题**: 注意力残留与认知惰性  
**关联场景**: `scenario_001`, `scenario_002`, `scenario_003`, `scenario_004`, `scenario_012`  
**轮播权重**: 2

| 字段 | 内容 |
|------|------|
| **理论依据** | 从任务 A 切换到 B 时，注意力不会完全转移——仍有部分“残留”在 A 上。重启中断的任务，需额外消耗 30%-40% 的脑能量（认知惰性）。 |
| **设计映射** | 这就是为什么主线任务切换后有 15 分钟保护期不推送干扰——让大脑的“神经去同步化”平稳完成。 |

### 4.2 认知卸载（替代性 vs 互补性）

**ID**: `kt_cognitive_offloading`  
**标题**: 认知卸载的双面性  
**关联场景**: `scenario_008`, `scenario_009`, `scenario_015`, `scenario_018`  
**轮播权重**: 2

| 字段 | 内容 |
|------|------|
| **理论依据** | 用外部工具释放认知带宽是人类的本能。但“替代性卸载”（AI 替你做判断）会导致能力退化；“互补性卸载”（AI 替你记忆，你做判断）则带来认知扩增。 |
| **设计映射** | pflow 只展示“谁在等你、等了多久”，永远不替你做“切不切”的决策——把判断题留给你，把监控交给系统。 |

### 4.3 元认知监控瓶颈（N+1 定律）

**ID**: `kt_metacognitive_bottleneck`  
**标题**: 元认知监控的代价  
**关联场景**: `scenario_010`, `scenario_011`, `scenario_006`  
**轮播权重**: 1

| 字段 | 内容 |
|------|------|
| **理论依据** | 人类大脑无法同时运行“当前任务”和“监控当前任务”——后者会占用近 50% 的执行控制资源。这就是为什么边工作边监控自己“有没有分心”几乎不可能。 |
| **设计映射** | 注意力遮罩层（透明度变化）和红绿灯三态，把监控“外包”给视觉皮层——你扫一眼就知道全局，不用费脑去记。 |

### 4.4 具身认知（物理环境外挂）

**ID**: `kt_embodied_cognition`  
**标题**: 物理环境即思维外挂  
**关联场景**: `scenario_006`, `scenario_007`, `scenario_019`（无活跃会话 / 全部空闲 / 长时间无输入）  
**轮播权重**: 1

| 字段 | 内容 |
|------|------|
| **理论依据** | 物理环境（屏幕布局、光标位置、便签）是思维最强大的外挂支架——视觉皮层能以无意识速度处理环境线索，无需动用前额叶。 |
| **设计映射** | pflow 不内嵌终端，就是让你用“物理性切换窗口”的动作来重置大脑上下文——肢体动作是最可靠的“清空缓存”指令。 |

### 4.5 中断恢复与保护期

**ID**: `kt_interruption_recovery`  
**标题**: 中断恢复的代价  
**关联场景**: `scenario_001`, `scenario_002`, `scenario_003`, `scenario_004`  
**轮播权重**: 1

| 字段 | 内容 |
|------|------|
| **理论依据** | 被中断后，平均需要 23 分钟才能回到原有的深度工作状态。中断越频繁，有效深度工作时间越短。 |
| **设计映射** | 提醒分数算法用“幂函数放大”机制，避免多个项目同时高亮——只有远超阈值的那个才推送通知，减少无效中断。 |

### 4.6 预测误差信号

**ID**: `kt_prediction_error`  
**标题**: 预测误差与判断信心  
**关联场景**: `scenario_014`（Agent 卡住）  
**轮播权重**: 1

| 字段 | 内容 |
|------|------|
| **理论依据** | 当我们自己得出答案时，大脑会产生“预测误差信号”作为奖励；当 AI 直接给出答案时，这个信号消失，长期会削弱判断信心。 |
| **设计映射** | 当 Agent 持续运行超 10 分钟时提醒你“可能卡住，建议检查”——让你重新介入判断，保持对工具输出的“异常监测”敏感度。 |

### 4.7 主线/支线策略的认知基础

**ID**: `kt_primary_secondary_strategy`  
**标题**: 为何强制设定 1 个主线  
**关联场景**: `scenario_010`, `scenario_011`, `scenario_018`（注意力失衡 / 多项目并行）  
**轮播权重**: 1

| 字段 | 内容 |
|------|------|
| **理论依据** | 工作记忆容量有限（约 4 个组块），超出容量的多线程管理本身就是一种认知负担——你花在“排序优先级”上的精力，本可以用来做实际工作。 |
| **设计映射** | 强制设定 1 个主线 + 最多 2 个支线，把“排序”这个决策前置化，让你在工作过程中不需要反复纠结“先做哪个”。 |

### 4.8 多任务并行幻觉

**ID**: `kt_multitasking_illusion`  
**标题**: 多任务只是快速切换的幻觉  
**关联场景**: `scenario_009`, `scenario_012`, `scenario_018`  
**轮播权重**: 1

| 字段 | 内容 |
|------|------|
| **理论依据** | 人类大脑本质上是串行处理器——所谓的“多任务并行”，只是在不同任务间极速切换产生的幻觉。每次切换都有能耗，且无法真正同时处理两件事。 |
| **设计映射** | 红绿灯状态（🟢/🟡/⚪）就是为了撕掉“并行”的伪装：此刻只有一个 🟡 的项目在占用你的思考排队名额。 |

### 4.9 组块化与路径即项目

**ID**: `kt_chunking`  
**标题**: 组块化认知与零归类设计  
**关联场景**: 通用（无特定军情关联，主要出现在轮播）  
**轮播权重**: 1

| 字段 | 内容 |
|------|------|
| **理论依据** | 人类长时记忆依靠“组块”（Chunking）压缩信息。把零散信息打包成有意义的单元，是大脑处理复杂信息的核心机制。 |
| **设计映射** | “路径即项目”——用目录路径作为天然分组依据，避免你消耗额外心力去手动维护分组。目录本身就是你大脑已经认可的认知组块。 |

### 4.10 正向反馈与多巴胺

**ID**: `kt_positive_feedback`  
**标题**: 正向反馈驱动持续专注  
**关联场景**: `scenario_008`, `scenario_015`（一切正常 / 今日高效完成）  
**轮播权重**: 1

| 字段 | 内容 |
|------|------|
| **理论依据** | 多巴胺系统在获得正向反馈时被激活，能增强持续专注的动机。小胜利的记录比大目标的激励更能维持日常动力。 |
| **设计映射** | 当一切正常或今日高效完成时，系统给出 ✅ / 🎉 级别的正向反馈——“继续保持”不是空话，是对你大脑奖励机制的调用。 |

### 4.11 决策疲劳与注意力调度

**ID**: `kt_decision_fatigue`  
**标题**: 决策疲劳与调度前置  
**关联场景**: `scenario_006`（无活跃会话，建议启动任务）  
**轮播权重**: 1

| 字段 | 内容 |
|------|------|
| **理论依据** | 每做一个决策都会消耗有限的认知资源。随着决策次数累积，后续决策的质量会下降——这就是“决策疲劳”。 |
| **设计映射** | 把“切不切”的判断前置到策略设定阶段（主线/支线），执行阶段只需要看状态、按计划行动，大幅减少执行过程中的决策次数。 |

### 4.12 认知卸载的边界（总结性）

**ID**: `kt_offloading_boundary`  
**标题**: 卸载的边界：保留不可让渡的阵地  
**关联场景**: 通用轮播（作为系列收尾）  
**轮播权重**: 1

| 字段 | 内容 |
|------|------|
| **理论依据** | 认知卸载不是“越彻底越好”。价值观判断、审美选择、生死攸关的直觉——这些领域的卸载会导致不可逆的能力丧失。 |
| **设计映射** | pflow 的边界感即是对此的回应：帮你“记住状态”，但永远不替你“做出选择”。你是统帅，兵权不可让渡。 |

## 6. API 设计

### 6.1 接口定义

在现有 `pflow suggest` 接口的返回结构中增加 `knowledge_tip` 字段：

```json
{
  "suggestions": [
    {
      "scenario_id": "scenario_001",
      "priority": 5,
      "level": "🔴",
      "message": "周报的 Hermes 会话已等待 8 分钟，需要你确认文件覆盖操作。",
      "action": "按 Enter 打开终端处理",
      "knowledge_tip": {
```

### 6.2 前端逻辑（伪代码）

```javascript
// 每隔 N 秒轮询 /api/suggest
async function refreshSuggest() {
  const data = await fetch('/api/suggest').then(r => r.json());
  
  // 取最高优先级建议
  const top = data.suggestions.reduce((a, b) => a.priority > b.priority ? a : b, null);
  
  if (top && top.knowledge_tip) {
    // 军情变化时切换知识锚点
    if (top.scenario_id !== currentScenarioId) {
      showKnowledgeTip(top.knowledge_tip);
      currentScenarioId = top.scenario_id;
    }
    // 如果 scenario_id 未变，保持当前内容不变
  } else {
    // 无匹配，展示通用轮播
    showGenericTip();
  }
}
```
