# v0.0.8：多 Agent 会话注意力管理系统

> 归档日期：2026-08-27 | 状态：✅ 已归档
>
> 本文档汇总本版本已经落地并验收的 backlog 条目，是版本范围和交付结果的历史记录。当前实现仍以代码、PRD、tech、design 和 handbook 为准。

## 版本概览

本版本完成了 pflow 从单一会话状态展示到多 Agent 会话调度工具的核心闭环：

```text
Agent 启动与会话发现
        ↓
项目归类与主线/支线策略
        ↓
Dashboard 状态展示与 Web 终端操作
        ↓
提醒分数、专注保护与动态注意力引导
```

交付范围覆盖四个阶段：基础可行性验证、Dashboard 与终端集成、项目策略管理、动态注意力引导及多 Agent 扩展。

## 交付清单

### 基础能力与部署（#0–#7）

- 完成 cc-connect 通信能力、tmux 会话托管和 Web 终端嵌入的可行性验证。
- 建成 Vue 3 + Naive UI Dashboard，支持会话列表、状态筛选、排序、自动刷新、详情抽屉和统计摘要。
- 提供 `pflow claude`、`pflow status`、`pflow probe <id>` 和 `pflow serve` 命令。
- 实现 tmux + ttyd Web 终端链路，支持从 Dashboard 进入对应 Agent 会话。
- 建立会话映射持久化和生命周期管理，并支持 Go embed 单二进制部署。

### 项目模型与策略管理（#8–#12）

- 采用“路径即项目”模型，以项目根路径作为归属标识，不引入额外项目实体。
- 使用最长前缀匹配将子目录会话自动归入项目；根目录 `/` 不允许标记为项目根。
- Dashboard 支持将工作目录识别为项目，并按主线、支线、普通和未归类分组展示。
- 建立 1 条主线 + 最多 2 条支线的策略引擎，切换 slot 时自动调整原项目状态。

### 注意力管理与交互（#13–#16）

- 实现提醒分数算法，综合等待时长、专注持续时间、今日累计时间和项目优先级。
- 实现双维度注意力呈现：Fog 雾化遮罩 + Marquee 高亮跑马灯。
- 实现专注模式和保护期，支持延长/停止专注，并抑制非关注项目的干扰。
- 支持普通项目、归档项目和项目卡片折叠状态记忆。
- 通过 tmux focus 事件同步会话绑定变化，覆盖 `/clear`、`/resume` 和重启等 session ID 变化场景。

### 军情哨与多 Agent（#17–#18、#22）

- 提供 `pflow suggest` 军情哨分析建议，覆盖紧急等待、主线空闲、注意力失衡、异常退出、时间提醒等场景。
- 新增 `pflow hermes`，将 Hermes Agent 纳入统一的会话启动与 Dashboard 监控流程。
- 实现 Hermes 会话扫描，支持导出数据解析、source 过滤、时间窗口、项目匹配、LastReq/LastResp 提取和 Gateway 状态富化。

### 会话映射与运行维护（#27–#35）

- 升级 Mapping 数据结构，补充 agentName、status、lastUpdated 和 pid 等运行信息。
- Claude 会话改用 `claude -n <name>` 与 `~/.claude/sessions/` JSON 扫描建立映射，保留旧截屏方案作为兼容开关。
- 增加 Claude 后台轮询，定期发现 session ID 变化并自动更新映射。
- Hermes 改用 `/status` 截屏解析会话 ID，替代 `hermes sessions export` 作为实时绑定方案。
- 优化 tmux 生命周期：阻止 Ctrl+Z 挂起、Agent 退出后自动销毁，并在启动时清理无映射的孤儿 `pflow-*` 会话。
- 新增 `pflow session list` 和 `pflow session destroy`，并优化 Dashboard 的终端映射展示。

### 知识反馈与每日启动（#36–#37）

- 新增 Knowledge Anchor 知识锚点，根据军情建议展示对应的认知科学依据，并在无关联建议时轮播通用卡片。
- 新增 Daily Boot 每日引导，以认知卸载、模式切换、目标锚定三幕帮助用户开始工作。
