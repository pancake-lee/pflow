### #54 Windows 独立应用打包

- **状态**：Done
- **分组**：平台扩展
- **背景**：Windows 桌面界面连接 Docker Linux 或 WSL 上的 pflow serve，本轮不读取原生 Windows Agent 会话。
- **方案**：用户已选择 Wails 桌面形态与 A（配置 HTTP 服务 URL）。exe 内嵌前端，在进程内代理现有 API；首次配置地址并保存到 Windows 用户目录，切换服务后重载界面。项目、日程及偏好由远端服务管理，桌面仅保存连接地址和日志。SSH 隧道由用户自行管理。Web 终端依赖独立 ttyd 端口及 WebSocket，本轮桌面入口明确禁用，Linux 浏览器版保持原有功能。目标机器需要 WebView2。
- **分析**：Linux 服务需能读取 Agent 数据并查询其 PID，推荐与 Agent 在同一容器运行。本轮复用已有 API，未来本地与多远端融合另见 #55。
- **任务列表**：
  - [x] 确定 Wails、单远端 HTTP 与 Web 终端支持范围。
  - [x] 实现连接配置、请求代理、错误提示和切换服务。
  - [x] 完成 Windows 打包及运行文档。
  - [x] 完成 AI 自动验证并交付真实 Windows 验收。
  - [x] （用户）完成 Windows 桌面运行验收。
- **验收**：双击 exe，配置地址后能查看 Linux 会话及编辑远端项目、日程；地址重启后保留；连接失败可修改地址；关闭窗口后进程退出；Linux 现有使用方式保持可用。
- **实施记录**：2026-10-13 完成 Wails v2.10.1 桌面入口、单远端代理与连接编辑入口。连接地址保存在 `~/.pflow/desktop.json`，日志保存在 `~/.pflow/logs/desktop.log`，不启动本地会话扫描服务或 SSH 子进程。Web 终端入口在桌面构建中关闭；关闭每日引导时仍能完成启动检查。中英文 README 已补充构建及 Docker/WSL/SSH 隧道连接说明，PRD 与 tech 已同步。
- **AI 自动验证**：`go test ./...`、`go vet ./...`、`go test -race ./internal/desktop` 通过；Windows 桌面入口及代理的 `go vet` 通过；`make build` 与最终 `make build-windows` 通过，前端类型及模板检查通过。代理集成测试覆盖请求方法/路径/查询/正文/响应、服务切换和配置重读、无配置/错误配置/网络失败、保存失败保留原连接，以及隔离环境中的真实远端项目增删。产物 `bin/pflow.exe` 约 19 MB，已核对为 Windows amd64 GUI 可执行文件。构建仅有既存前端 chunk 大小提示。

## 终端交互

### #65 Codex 原生鼠标滚动被 tmux 复制模式截获

- **状态**：Done
- **分组**：终端交互
- **背景**：用户反馈新版 Codex 自行处理鼠标滚动，使用 pflow 托管后向上滚动进入 tmux 复制模式，无法浏览 Codex 会话旧内容。
- **分析**：2026-10-13 检查发现 `~/.tmux.conf` 及当前 tmux server 的 root 键表均存在无条件进入复制模式的 WheelUpPane 自定义绑定。当前 `pflow-pflow-codex` 窗格的 `mouse_any_flag=1`、`alternate_on=1`，应用已启用鼠标事件接收。pflow 的会话启动代码没有配置滚轮绑定；此次冲突来自用户 tmux 规则。tmux 官方支持根据应用鼠标状态转发原始事件，参见 [官方配置示例](https://github.com/tmux/tmux/wiki/Recipes#send-up-and-down-keys-for-the-mouse-wheel)。
- **方案**：2026-10-14 用户选择 B。由 pflow 调用 tmux 公开命令，在运行时为托管会话启用专用键表及鼠标接收。复制既有 root 键表中的快捷键与鼠标操作，仅替换上下滚轮分发：应用开启鼠标或窗格处于复制模式时转发原始事件，否则向上滚动进入 tmux 复制模式。前缀键表与其他会话的 root 键表保持原样。新建、重新接入及 Web 终端接入统一应用策略；不修改 `~/.tmux.conf`，不新增依赖。
- **任务列表**：
  - [x] 用户选择运行时配置托管会话专用键表。
  - [x] 按所选范围修复滚轮事件分发，上下滚动均兼容应用鼠标处理与复制模式。
  - [x] AI 核对配置及事件分发规则，再交付真实终端滚动验收。
  - [x] （用户）在现有 Codex 会话滚动查看旧内容，确认普通终端滚动仍符合预期。
- **验收**：Codex 接收原始滚轮事件并能浏览旧内容；应用未启用鼠标时保留 tmux 历史滚动；已有复制模式仍能滚动；无需重启 Codex 或销毁现有会话。
- **实施记录**：2026-10-14 在会话管理器中通过公开 `list-keys` 命令复制 root 绑定，使用标准 `source-file` 命令从 stdin 加载到托管会话共用的 `pflow-root` 专用键表。仅改写绑定目标表与上下滚轮规则，启用会话级 mouse/key-table 选项。启动器的新建与重连、普通终端创建及 Web 终端接入均使用同一配置逻辑。再次接入时刷新 root 快捷键快照，清除已删除的旧绑定；前缀键与复制模式键表保留原样。中英文 README 及技术说明已同步，未修改真实 tmux server 或用户配置文件。
- **AI 自动验证**：`go test ./...`、`go vet ./...`、`make build`、`git diff --check` 通过，产物为 `bin/pflow`。隔离 tmux 集成测试覆盖 root/prefix 不变、非托管会话 mouse/key-table 不变、带引号及重复属性的快捷键复制、重新配置清除旧快捷键和会话不存在错误；Python 标准库 PTY 测试实际发送上下滚轮、普通文本、自定义 F12、复制模式滚动和前缀分离事件，全部通过。测试 server 使用独立 socket，并在退出时执行 `kill-server` 清理。构建仅有既存前端 chunk 大小提示。
- **（用户）验收操作**：在该 Codex 会话所有已连接终端按 `Ctrl+B`、`D` 分离，然后在原项目目录用新版 `bin/pflow` 执行原 Codex 启动命令（默认名称时为 `/root/code/pflow/bin/pflow codex`，自定义名称保留原 `-name`），重新接入后上下滚动浏览旧内容。
- **预期结果**：既有 Codex 进程继续运行，滚轮能浏览 Codex 历史内容，不自动进入 tmux 复制模式；普通终端滚动符合原有预期。
- **最小回传**：回复「#65 已通过」；失败时说明滚动是否进入复制模式及看到的现象。
