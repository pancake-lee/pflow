# 日程编辑与模板交互 UX 审计

## 结论

- **总分：3.4 / 10，不通过。** 当前实现不是“体验有待打磨”，而是日程编辑的关键写入链路无法可靠闭环：用户可以无提示丢失草稿、把执行记录污染进模板、保存后看不到即时结果。
- 本报告用通用前端产品标准审阅：Nielsen 可用性启发式（系统状态可见性、用户控制、错误预防/恢复、一致性）、表单 UX、危险操作保护、响应式/可访问性，以及前后端数据契约。构建与后端状态机通过不抵消关键任务失败。

## 审计范围与用户任务

范围为 `ScheduleEditor.vue`、`SchedulePanel.vue`、日程 API 和 `internal/schedule` 持久化层，覆盖以下完整任务：选择日期 → 编辑/保存 → 关闭后确认结果；选择/应用/另存/删除模板；完成/跳过后推进；刷新和失败后的状态一致性。

## 分维度评分

### 任务闭环与可恢复性：2.0

得分点：保存实际日程、另存模板和删除模板都有成功 toast；当前/下一项的完成与跳过能调用独立接口。

失分点：日期原生 `change` 直接调用 `load()` 覆盖 `items`（`ScheduleEditor.vue:27-36, 99`）；应用模板直接替换 `items`（75-80）；关闭、删除均没有未保存或危险操作确认（82-90, 109, 131）。保存后 Dashboard 不会被通知刷新，只会等待面板的 30 秒定时请求（`SchedulePanel.vue:66-69`）。这些路径均没有撤销、草稿或恢复状态。

### 表单交互与信息架构：3.0

得分点：时间、内容、专注和休息都有可编辑控件；新增项的默认休息为 10 分钟；窄屏会纵向排列表单字段。

失分点：标题写“今日日程编辑”，但页面允许编辑任意日期，日期上下文错误；日期切换只有一个裸原生输入，没有相邻日期导航、未保存状态或该日期保存状态。每项没有序号、时段摘要、排序能力或“持续到当天结束”控件；保存失败只给通用文案，不能定位哪一项、哪一规则失败。按产品承诺的排序、冲突提示、末项能力没有可用界面。

### 模板生命周期：2.0

得分点：应用只改当前内存编辑值，另存与删除有独立接口；应用时会重新分配临时项 id。

失分点：模板下拉框的选择即应用，缺少预览、当前选择状态和可撤销确认；保存区与模板列表重复呈现模板而没有明确层级。删除无确认，另存与删除没有 loading/禁用态；请求被拒绝时缺少具体错误。更关键的是实际日程项的 `status`、`completed_at` 会原样传给模板 API（`ScheduleEditor.vue:61-65`），模板模型也保留这两个字段（`schedule.go:15-34`），直接违背“模板不带执行记录”。

### 数据完整性与状态机：2.0

得分点：JSON 使用临时文件加 rename；保存时检查日期、基本时间格式、正时长和开始时间递增；完成/跳过会记录时间，首次定位后使用 `CurrentID` 防止墙钟自动推进。

失分点：保存日程以整个 `Day` 直接替换（`server.go:194-215`），会抹掉未随编辑器提交的 `CurrentID`，并允许删除/修改已有执行项而不确认；不会保留或匹配历史记录。`validate` 只检查开始时间递增，不检查相邻时段是否重叠、id 唯一、小时/分钟下界或 `until_end`，且 `UntilEnd` 没有任何业务行为（`schedule.go:68-85`）。首次定位后的 `Save` 错误被忽略（`server.go:163-165`）。

### Dashboard 状态与反馈：5.0

得分点：当前项、下一项、自由日程和 break 有清晰的基础分层；当前项推进不依赖时间自动发生；卡片在窄屏将操作区换行；下一项有渐隐与 hover 临时查看。

失分点：面板请求失败会静默消失（`SchedulePanel.vue:17-27, 77`），完成/跳过失败也无任何反馈（29-37）；“编辑”只在当前卡片，且弹框关闭或保存不触发同步。休息中没有显示剩余时间，下一项的模糊会在键盘焦点时无法临时清晰化；颜色是表达状态的主要手段，状态文案不足以补齐失败/加载情形。

### 布局、响应式与可访问性：4.0

得分点：编辑器使用 Naive UI 输入控件，主要字段设有 aria-label；960px 弹框宽度与 760px 断点能避免桌面行在小屏直接横向溢出。

失分点：桌面一行同时容纳五个编辑字段、两个文字标签和删除操作，缺少字段标签/分组，扫描与对齐成本高；移动端退化为很长的纵向表单，缺少单项折叠或固定保存入口。日期使用原生暗色控件而其他输入使用 Naive UI，视觉和键盘行为不一致。模板区把“应用”“另存”“删除”混在同一视觉层级，破坏危险操作的区分。

### 代码与自动化验证：5.0

得分点：`GOTOOLCHAIN=local make test`、`make vet` 与前端生产构建均通过；后端状态机覆盖首次定位、自由时段、末项和手动推进。

失分点：没有前端组件或浏览器测试；API 测试也未覆盖模板隔离、重复/重叠时段、保存覆盖、日期切换、读取/保存失败、即时同步。#49 暴露过一次 HTTP 非安全上下文下 `crypto.randomUUID` 直接中断模板流程，说明关键浏览器环境未被测试。构建还报告单个压缩后 JS chunk 为 752.97 kB，高于 Vite 默认 500 kB 警戒线。

## 对 #46“8.0”评分的复核

此前第二轮报告仅列出四项得分点和构建命令，没有逐维度得分、失分点、编辑器实际任务演练、模板数据隔离验证或验收清单回写。它将“后端存在 CRUD + 构建通过”当作“用户能安全完成工作”的代理指标；这不是通用前端 UX 评估可接受的证据链。

按本次标准，阻断级的数据污染和无提示丢稿会使“任务闭环”和“数据完整性”均落在 1–3 分区间，因此总体不可能达到 8.0。46 的历史分数应视为**范围不足的实现复评**，不能再作为日程编辑体验基线。
