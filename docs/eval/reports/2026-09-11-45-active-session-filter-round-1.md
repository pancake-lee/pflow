# #45 活跃会话展示数量筛选，第一轮评估

## 结论

- **总分：7.4 / 10，不通过**
- 已验证：Go 静态检查、完整测试及前端类型/生产构建通过。

## 得分点

- Active 输入位于 Inactive 左侧，两个参数独立传入 Dashboard API。
- Claude、Hermes、Codex 均已按项目和状态分组，使用最近活动优先的截断语义。
- `active=1`、`inactive=0` 时主线和支线卡片不渲染副会话区域。

## 失分点

- 新的活跃截断缺少 Claude/Hermes/Codex 的跨项目、混合状态、0 上限和稳定排序回归测试。
- 设置中心尚未保存 Active 默认上限，重启后只能回到无限制默认。
- 紧凑组合没有独立前端结构测试。

## 待规划问题

- 为三类扫描器和紧凑卡片补齐最小回归覆盖。
- 将 Active 默认上限纳入设备级显示设置，并保持 0 的无限制语义。
